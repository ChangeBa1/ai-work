# 開発ルール

### ■間違い考え方

* 動けばいい　✖️
* 後でなせばいい　✖️
* とりあえず動かしてみてから考えよう  　✖️
* まあいいか、これでいいか  　✖️
* 言われた通りにやる、言ったことをそのままやる  ✖️
* とりあえず動けばいい（いい加減な開発、仮の対応をするのは非常に問題です）  ✖️
*  日本側が指摘した問題を直せばそれで終わり（これは日本語の完全な誤解です）  ✖️
* これは私の責任ではない、あれこれを参考にして開発するもの　✖️
* 何も言わないと、勝手に修正されることが発生する ✖️

### ■MVC

* Model：ビジネスロジックと呼ばれる部分に該当(BusinessObject)。アプリケーションデータやビジネスルール、関数、DBアクセス、データ管理などを担当。
* View：レイアウト部分に相当。UIを表示するコンポーネントであり、データ入力、デザインやレイアウトに関わるアプリケーションのフロントエンド部分となる。レシートも情報のレイアウトと捉え、UIとして管理している。
* Controller：ModelとViewの仲介役を担い、Viewから受けたデータ(以下、Event)を、Model(実体としてのCommand)に渡し、Modelでの処理結果をViewに戻す(Observerを呼ぶ)役割。

### ■フレームワーク

* イベントについて

    * <custom data-type="smartlink" data-id="id-0">https://retailai.atlassian.net/wiki/spaces/POSSYS/pages/2970550410</custom> 
    * UI、Device、Observerのみがイベントをトリガーできる
    
* コマンドについて

    * Tranプロパティ変更等の処理を書かない
    * コマンド引継可
    
* UIについて

    * Tranプロパティ変更等の処理を書かない
    * Timer使用の必要性要検討
    
* ビジネスロジック

    * ビジネス間相互引用禁止
    

### ■コーディング

* １Class１File
* 命名規則を守る
* ハードコーディングを書かない
* 新しい設定は追加されますが、特別な理由がなければ最後に追加するのがベストです
* データ型変換int.TryParse("123", out int data);　✖️
* NULLポインタ例外回避のため、オブジェクトのNullチェックを入れる
* プロジェクトにアナライザー追加、StyleCop.AnalyzersとPOS4U.ruleset
