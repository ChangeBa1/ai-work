# テストプロセス

* **開発ライフサイクル**

    * 企画→設計→開発実装→**テスト**→導入→運用
    
* **テストプロセス：**

    * 仕様分析→テスト計画→テスト設計→テスト実装（準備）→**テスト実行**→テスト完了
    

| **タスク** | **仕事内容** | **成果物** |
| --- | --- | --- |
| 仕様分析 | **要件の分解**: 各機能要件を細分化し、具体的なテストシナリオやテストケースに落とし込みます。 **リスク分析**: 重要度やリスクを考慮して、テストの優先順位を決定する |  |
| テスト計画 | テストの目的：テストを行う理由や目標を明確 テストの範囲：テスト対象の機能や要件、テストしない部分を定義する テストの方法：テスト手法を明確します(手動テスト、自動テスト、単体テスト、統合テスト) テスト環境：テストを実施する環境を明確する テストの評価基準：テスト成功基準を設定する、 テストスケジュール：テスト開始日、終了日、主要なマイルストーンを設定する | [テスト計画書](https://docs.google.com/spreadsheets/d/1Zl7rlWxX_Y5Ii3rGaIMGSOkyYtrFkm9V/edit?gid=2091413339#gid=2091413339) |
| テスト分析＆設計 | **テスト分析**:テスト対象の要件や仕様を詳細に理解し、具体的なテストの範囲を明確にする。  
**テスト設計**:実際のテストケースを具体的に設計し、テストの実施方法を明確してテストデータを作成する | テストケース |
| テストケースレビュー | テストケースが正確で効果的であることを確認するためのプロセスです. 各テストケースについて、以下の点を確認します： 要件に対する適合性 テストの網羅性 実行手順の明確さ 期待結果の正確さ テストデータの適切さ | テストケース |
| テスト実行 | テスト計画に基づき、テストケースを一つずつ実行し、事前に定義した期待結果と実際の結果を比較します。 | テストログ、バグ一覧 |
| テスト完了 | テストの結果をレポートします | [テスト報告書](https://docs.google.com/spreadsheets/d/1pWf37o_h2R_AC_Wjgw8AnYUSOYYdaV_q/edit?usp=drive_web&ouid=106469335417401423171&rtpof=true) |
