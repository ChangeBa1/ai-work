# デザインパターン

## **デザインパターンと**は

**デザインパターン**は、 ソフトウェアの設計でよく起きる問題に対する典型的な解決方法です。パターンの一つ一つは、 自分のコードの設計の一つ一つは、 自分のコードの設計上の問題に合わせて調整可能な設計図のようなものです。

## 主要なデザインパターンの一覧

### **生成に関するパターン**

| パターン名 | 概要 |
| --- | --- |
| [Abstract Factory](https://ja.wikipedia.org/wiki/Abstract_Factory_%E3%83%91%E3%82%BF%E3%83%BC%E3%83%B3) | 関連する一連の[インスタンス](https://ja.wikipedia.org/wiki/%E3%82%A4%E3%83%B3%E3%82%B9%E3%82%BF%E3%83%B3%E3%82%B9)を状況に応じて、適切に生成する方法を提供する。 |
| [Builder](https://ja.wikipedia.org/wiki/Builder_%E3%83%91%E3%82%BF%E3%83%BC%E3%83%B3) | 複合化されたインスタンスの生成過程を隠蔽する。 |
| [Factory Method](https://ja.wikipedia.org/wiki/Factory_Method_%E3%83%91%E3%82%BF%E3%83%BC%E3%83%B3) | 実際に生成されるインスタンスに依存しない、インスタンスの生成方法を提供する。 |
| [Prototype](https://ja.wikipedia.org/wiki/Prototype_%E3%83%91%E3%82%BF%E3%83%BC%E3%83%B3) | 同様のインスタンスを生成するために、原型のインスタンスを複製する。 |
| [Singleton](https://ja.wikipedia.org/wiki/Singleton_%E3%83%91%E3%82%BF%E3%83%BC%E3%83%B3) | ある[クラス](https://ja.wikipedia.org/wiki/%E3%82%AF%E3%83%A9%E3%82%B9_(%E3%82%B3%E3%83%B3%E3%83%94%E3%83%A5%E3%83%BC%E3%82%BF))について、インスタンスが単一であることを保証する。 |

### **構造に関するパターン**

| パターン名 | 概要 |
| --- | --- |
| [Adapter](https://ja.wikipedia.org/wiki/Adapter_%E3%83%91%E3%82%BF%E3%83%BC%E3%83%B3) | 元々関連性のない2つのクラスを接続するクラスを作る。 |
| [Bridge](https://ja.wikipedia.org/wiki/Bridge_%E3%83%91%E3%82%BF%E3%83%BC%E3%83%B3) | クラスなどの実装と、呼び出し側の間の橋渡しをするクラスを用意し、実装を隠蔽する。 |
| [Composite](https://ja.wikipedia.org/wiki/Composite_%E3%83%91%E3%82%BF%E3%83%BC%E3%83%B3) | 再帰的な構造を表現する。 |
| [Decorator](https://ja.wikipedia.org/wiki/Decorator_%E3%83%91%E3%82%BF%E3%83%BC%E3%83%B3) | ある[インスタンス](https://ja.wikipedia.org/wiki/%E3%82%A4%E3%83%B3%E3%82%B9%E3%82%BF%E3%83%B3%E3%82%B9)に対し、動的に付加機能を追加する。Filterとも呼ばれる。 |
| [Facade](https://ja.wikipedia.org/wiki/Facade_%E3%83%91%E3%82%BF%E3%83%BC%E3%83%B3) | 複数のサブシステムの窓口となる共通の[インタフェース](https://ja.wikipedia.org/wiki/%E3%82%A4%E3%83%B3%E3%82%BF%E3%83%95%E3%82%A7%E3%83%BC%E3%82%B9_(%E6%83%85%E5%A0%B1%E6%8A%80%E8%A1%93))を提供する。 |
| [Flyweight](https://ja.wikipedia.org/wiki/Flyweight_%E3%83%91%E3%82%BF%E3%83%BC%E3%83%B3) | 多数のインスタンスを共有し、インスタンスの構築のための負荷を減らす。 |
| [Proxy](https://ja.wikipedia.org/wiki/Proxy_%E3%83%91%E3%82%BF%E3%83%BC%E3%83%B3) | 共通のインタフェースを持つインスタンスを内包し、利用者からのアクセスを代理する。Wrapperとも呼ばれる。 |

| パターン名 | 概要 |

| [Interpreter](https://ja.wikipedia.org/wiki/Interpreter_%E3%83%91%E3%82%BF%E3%83%BC%E3%83%B3) | 構文解析のために、文法規則を反映するクラス構造を作る。 |
| [Iterator](https://ja.wikipedia.org/wiki/Iterator_%E3%83%91%E3%82%BF%E3%83%BC%E3%83%B3) | 複数の要素を内包するオブジェクトのすべての要素に対して、順番にアクセスする方法を提供する。[反復子](https://ja.wikipedia.org/wiki/%E5%8F%8D%E5%BE%A9%E5%AD%90)。 |
| [Mediator](https://ja.wikipedia.org/wiki/Mediator_%E3%83%91%E3%82%BF%E3%83%BC%E3%83%B3) | オブジェクト間の相互作用を仲介するオブジェクトを定義し、オブジェクト間の結合度を低くする。 |
| [Memento](https://ja.wikipedia.org/wiki/Memento_%E3%83%91%E3%82%BF%E3%83%BC%E3%83%B3) | データ構造に対する一連の操作のそれぞれを記録しておき、以前の状態の復帰または操作の再現が行えるようにする。 |
| [Observer](https://ja.wikipedia.org/wiki/Observer_%E3%83%91%E3%82%BF%E3%83%BC%E3%83%B3) ([出版-購読型モデル](https://ja.wikipedia.org/wiki/%E5%87%BA%E7%89%88-%E8%B3%BC%E8%AA%AD%E5%9E%8B%E3%83%A2%E3%83%87%E3%83%AB)) | インスタンスの変化を他のインスタンスから監視できるようにする。Listenerとも呼ばれる。 |
| [State](https://ja.wikipedia.org/wiki/State_%E3%83%91%E3%82%BF%E3%83%BC%E3%83%B3) | オブジェクトの状態を変化させることで、処理内容を変えられるようにする。 |
| [Strategy](https://ja.wikipedia.org/wiki/Strategy_%E3%83%91%E3%82%BF%E3%83%BC%E3%83%B3) | [データ構造](https://ja.wikipedia.org/wiki/%E3%83%87%E3%83%BC%E3%82%BF%E6%A7%8B%E9%80%A0)に対して適用する一連の[アルゴリズム](https://ja.wikipedia.org/wiki/%E3%82%A2%E3%83%AB%E3%82%B4%E3%83%AA%E3%82%BA%E3%83%A0)を[カプセル化](https://ja.wikipedia.org/wiki/%E3%82%AB%E3%83%97%E3%82%BB%E3%83%AB%E5%8C%96)し、アルゴリズムの切り替えを容易にする。 |
| [Template Method](https://ja.wikipedia.org/wiki/Template_Method_%E3%83%91%E3%82%BF%E3%83%BC%E3%83%B3) | あるアルゴリズムの途中経過で必要な処理を抽象メソッドに委ね、その実装を変えることで処理内容を変えられるようにする。 |
| [Visitor](https://ja.wikipedia.org/wiki/Visitor_%E3%83%91%E3%82%BF%E3%83%BC%E3%83%B3) | データ構造を保持するクラスと、それに対して処理を行うクラスを分離する。 |
