# 7.1.ログ

\
logbackフレームワークを利用する \
■ ログ定義 \
　　⇒ ログレベル \
　　　ログレベルには、以下の種類がある。 \

<table class="wrapped">
<tbody>
<tr>
<th><span>ログレベル </span></th>
<th><span>ログレベルの識別文言 </span></th>
<th><span>定義</span></th>
</tr>
<tr>
<td><span>ERROR</span></td>
<td><span> -ERROR-</span></td>
<td><span>アプリケーションの継続に支障をきたす問題が発生したことを示す。 </span><br />
<span> 監視が必須であるが、通報および対応にFATALレベルほどの緊急性がない。</span></td>
</tr>
<tr>
<td><span>WARN </span></td>
<td><span>-WARN-</span></td>
<td><span>アプリケーションの継続に影響を与えるものではないが、警告として記録すべき事象が発生したことを示す。 </span><br />
<span> 監視や即対応が必要なものではないが、定期的に発生状況を確認し、必要に応じて改善につなげることが </span><br />
<span> 望ましい。</span></td>
</tr>
<tr>
<td><span>INFO</span></td>
<td><span> -INFO-</span></td>
<td><span>本番運用時にアプリケーションの情報を出力するログレベル。アクセスログや統計ログが該当する。 </span><br />
<span> INFOレベルのログは、以下の場合に適しています。 </span><br />
<span> ・利用者の重要な操作と関連するログ </span><br />
<span> ・業務フローと関連するログ </span><br />
<span> ・リクエストとレスポンス情報の処理と関連するログ </span><br />
<span> （リクエストURL、パラメータ、レスポンスステータスコード、各プロセスの実行開始時刻と終了時刻など）</span></td>
</tr>
<tr>
<td><span>DEBUG</span></td>
<td><span> -DEBUG-</span></td>
<td><span>開発時にデバッグ情報を出力するログレベル。SQLログや性能ログが該当する。</span></td>
</tr>
</tbody>
</table>

\
\
■ ログファイルごとのフォーマット \
　　⇒ ログフォーマット定義 　

<table class="wrapped">
<tbody>
<tr>
<td><span>&lt;ログ出力日時&gt; - &lt;ログレベル&gt; - [&lt;実行時ID&gt;] </span><br />
<span>req_id = [&lt;リクエストID&gt;] user_id = [&lt;ユーザID &gt;] &lt;メッセージ&gt;</span></td>
</tr>
</tbody>
</table>

※ \<論理名\>：可変となる要素(プレースホルダ)を表す(例：\<ログ出力日時\>)。これ以外の個所はリテラルである。 \
※ 表示の都合上、折り返しがあるが、実際の出力時は１行で出力される。 \
\
⇒ 各要素の説明 \

|  |  |  |
|----|----|----|
| 論理名  | 物理名  | 説明 |
| ログ出力日時  | \$date\$  | ログ出力日時 |
| ログレベル |  \$logLevel\$  | ログレベルを識別する文言。文言の種類は、ログレベルの定義を参照。 |
| 実行時ID  | \$executionId\$  | スノーフレークアルゴリズムより実行IDを生成。 |
| リクエストID  | \$requestId\$  | アプリケーション処理の最小単位に対して付与されるID。 |
| ユーザID  | \$userId\$  | ログインユーザID |
| メッセージ  | \$message\$  | メッセージ内容 |
