# 7.1log（汉语）

log目的：

　为了操作系统，调查使用的业务量，系统停机时间，输出日志和消息作为信息源，以调查业务错误等的原因。 　　      \
输出日志很重要，因为在调试时合并日志输出可以大大提高分析的工作效率。 \
实现方法：

　　将 SLF4J（接口）+ Logback（实现）用于日志记录库 \
\
■ 日志说明 \
根据日志的紧急程度和用途，按如下方式设置日志级别 \

|  |  |  |  |
|----|----|----|----|
| 等级  | 概要  | 说明  | 是否需要对应 |
| ERROR  | -ERROR- | 意外的其他运行时错误。 假设立即输出到控制台等。 |  需要采取的行动 |
| WARN  | -WARN- | 业务错误  | 根据确认结果进行响应。 |
| INFO |  -INFO- | 运行时的一些值得注意的事件（例如开始或结束）。 消息应保持简短  | 无需执行任何操作 |
| DEBUG  | -DEBUG-  | 系统之详细信息  | 不输出 |
| TRACE  | -TRACE- | 调试信息  | 不输出 |

■ 格式化日志 \
%d{YYYY-MM-dd HH:mm:ss.SSS} %X{serviceName}.%X{HOSTNAME} %X{request_id:--} %X{user_id:--} %-5level %logger{36} - %msg%n \
•serviceName : {system}\_{service}。例：ilcm_api_prd \
•HOSTNAME : {docker_container_name} 或{function_compute_name} 。　 \
•serviceName、HOSTNAME、user_idとrequest_id需要在MDC中设置。 \
\
\
■ 格式化日志实现 \
 1. 对于Ctrl的需要利用AOP实现，出参入参打印，日志格式需要规范。 \
2. 日志打印结合MDC参数设置，MDC需要全局设置。 \
3. 业务中的如 Service 如有关联查询，如 ServiceA 调用 ServiceB 需要打印对应的调用结果 \
或根据业务自行输出文字 或根据业务自行输出文字 \
4. 业务中的增删改需要打印对应参数及日志。 \
ServiceImpl 日志记录： \
•增加（Create）操作：通常建议记录创建操作的日志，以便跟踪新数据的创建。这对于审计和业务追踪非常有用。 \
•删除（Delete）操作：建议记录删除操作的日志，尤其是在重要数据上执行删除操作。这可以帮助追踪数据的生命周期和记录数据被删除的时间点。 \
•修改（Update）操作：通常建议记录修改操作的日志，以便追踪数据的变化。这对于审计和调试非常有用。 \
•查询（Search）操作：查询操作通常不需要详细的日志记录，除非它们是特定的业务查询或性能监控的一部分。通常，查询操作的日志记录会较少。 \
日志通常发生在以下位置： \
操作开始前：在执行具体的增删改查操作之前记录日志，以记录操作的开始时间和相关信息。这有助于跟踪操作的执行。 \
操作完成后：在增删改查操作完成后记录日志，以记录操作的结果和结束时间。这有助于跟踪操作的成功或失败，并记录操作的执行时间。 \
异常处理中：如果操作过程中发生了异常，应该在异常处理代码块中记录日志，以记录异常的详细信息。这对于故障排除非常重要。
