# Source mapping for legacy POS4U UI

## Map WPF

Inspect:

- `x:Class`, root type, `x:Name`/`Name`;
- `AutomationProperties.AutomationId` and `.Name`;
- event attributes, routed events, `Command`, and `CommandParameter`;
- `Grid.Row`/`Grid.Column`, panels, alignments, margins, visibility;
- merged resources, styles, templates, triggers, and dynamic resources;
- code-behind event subscriptions and runtime-created controls;
- navigation/content host assignments;
- custom controls and `OnCreateAutomationPeer`.

Do not calculate final pixels from Grid definitions. Use layout metadata only to help join runtime nodes to source.

For controls generated by a `DataTemplate` or `ItemsControl`, map the runtime item to:

```text
template source file + template key/data type + item identity/index
```

Do not pretend each generated item has a unique source line.

## Map WinForms

Inspect the actual form/control `*.Designer.cs`, not generated resource or typed-data-set designers. Map:

- field assignment and concrete type;
- `Name`, `AccessibleName`, `AccessibleRole`;
- `Text`, `Tag`, `Location`, `Size`, `Anchor`, `Dock`;
- parent `Controls.Add` relationships;
- event subscriptions;
- runtime-created controls in constructors/load handlers;
- custom painting and hit-testing.

Treat designer `Location` and `Size` as design/client coordinates, not current physical screen bounds.

## Trace handlers

Follow both declarative and programmatic wiring:

```text
Click="BtnCash_Click"
button.Click += this.BtnCash_Click
Command="{Binding PayCashCommand}"
```

For code-behind:

1. Locate the handler declaration.
2. Read the complete method body.
3. Follow helper calls, service fields, interfaces, factories, and navigation.
4. Locate implementations when a call is interface-based.
5. Continue through `Business`, `LogicService`, `Device`, or data boundaries when relevant.
6. Stop at a meaningful domain operation and retain the call chain.

For MVVM:

1. Resolve the binding DataContext at runtime.
2. Identify the command property and concrete view-model type.
3. Find command construction/execution.
4. Trace the execute delegate/method to the service boundary.

Regex script output is a search accelerator. It cannot prove dynamic dispatch, partial classes, reflection, IoC resolution, or generated command wiring.

## Join hosted controls

For `WindowsFormsHost`:

1. Locate the host in XAML and WPF visual tree.
2. Capture its physical bounds and HWND descendants.
3. Inspect the hosted HWND with UIA2/MSAA.
4. Match the WinForms runtime node to Designer.cs or construction code.
5. Retain both the WPF host path and WinForms child path in `locatorFallbacks`.

For `ElementHost`, reverse the direction.

## Assign confidence

Use:

- `high`: exact explicit AutomationId or unique source name plus matching ancestry/type.
- `medium`: unique source name or several consistent structural signals.
- `low`: localized text, approximate geometry, or heuristic call tracing.
- `unmapped`: insufficient evidence.

Attach evidence:

```json
{
  "sourceMappingConfidence": "medium",
  "sourceMappingEvidence": [
    "runtime AutomationId empty",
    "runtime class Button",
    "x:Name btnCash unique in PaymentWindow.xaml",
    "parent path and sibling order match"
  ]
}
```

## Detect automation debt

Flag:

- missing/duplicate AutomationIds;
- localized `Name` used as sole locator;
- clickable custom control without Invoke/Selection/etc.;
- invisible automation children for meaningful sub-actions;
- controls with empty/invalid bounds while visibly rendered;
- owner-drawn controls without accessible hit targets;
- event handlers that branch by localized text;
- physical-click-only operations;
- identifiers that change across locales.

Recommend stable domain-oriented IDs such as `Payment.Cash`, not display text or volatile numeric indexes.
