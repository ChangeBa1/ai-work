# Feature Specification: 结构化元素身份主键（element-identity-key）

**Feature Branch**: `025-element-identity-key`

**Created**: 2026-08-06

**Status**: Draft

**Input**: User description: "元素记忆的身份主键从『自然语言描述』改为结构化元素身份，使
feature 015 建立的元素记忆真正可命中。实测 4 次真实 run 中 memory_hits.element_memory
全部为 0；根因是 Planner 每轮现场生成的自然语言目标描述被 strip/lower 后直接当作
element_memories 主键精确匹配。"

## Background & Problem

Feature 015（page-element-memory）已交付 page / element 记忆的完整写入与查询链路，以及
「页面高相似 + 目标匹配 + 邻域模板校验 → 跳过 Grounder 直点」的产品路径。但在多轮真实
回归中，报告里的 `memory_hits.element_memory` **持续为 0**——记忆被写入却从未被读中。

根因不是存储或模板匹配本身，而是**主键选择错误**：

- 写入与查询均以 Planner 本轮生成的自然语言目标描述（经空白裁剪与小写化）作为
  `target_label` 精确匹配键；
- 同一物理控件在不同轮次的措辞不稳定（例如短标签「小計」与长描述「屏幕右下角的小計
  按钮」），归一化后仍不相等；
- 因此同一控件的第二次出现几乎必然被当成「新标签」，命中率趋近于 0。

本 feature 不重做 015 的记忆通道，而是把「谁是同一个控件」从**不稳定自然语言主键**
改为**稳定的结构化元素身份**，使已有写入-命中-降级闭环真正生效。

## Clarifications

### Session 2026-08-06

- Q: 几何如何参与元素身份相等判定（坐标空间与容差）？ → A: 采用画面归一化中心点
  \((x/w, y/h \in [0,1])\) 并量化到固定网格单元作为身份几何分量；同网格单元才视为几何
  相等（容差 = 格宽）。绝对像素 bbox 仍存储供点击与模板校验。MUST NOT 使用应用容器
  相对坐标（黑盒无控件树）。跨分辨率直点仍由 015 页面分辨率门槛禁止。
- Q: 可见文本归一化到什么程度？ → A: **深度日文表面+假名归一化**：在 NFKC、大小写
  折叠、空白折叠之上，再对假名做可配置的脚本级折叠（含半角片假名、清浊音等确定性
  规则）。MUST NOT 做同义改写、子串包含式模糊相等。规则 MUST 为通用文字处理，MUST NOT
  嵌入被测应用业务词表（Constitution VI）。
- Q: 同画面多候选（如多行同名按钮）如何消歧？ → A: **保守：候选 ≥2 则未命中**。仅当
  （画面身份 + 归一化文本 + 几何网格等）将可检索记忆唯一收窄为 1 条时才允许进入后续
  模板校验/直点；否则 MUST 降级并审计为身份不唯一（如 `identity_ambiguous`）。MUST NOT
  用「最近成功」、序数猜测或随机选取做消歧。
- Q: 存量 element_memories 如何处理？ → A: **整表作废重建**。启用新身份逻辑后，以自然
  语言 `target_label` 为主键的旧记录一律不可参与命中（删除或隔离/标记
  `legacy_invalid`，plan 选定物理手段）；仅按新身份写入的记录可被命中。MUST NOT
  惰性迁移猜测身份，MUST NOT 双写并行命中。
- Q: 命中后模板校验是否可跳过？误命中口径与上限？ → A: **强制模板校验**，不得因高
  置信或连续成功跳过邻域模板校验。**误命中** = 已执行元素记忆直点，且该次独立验证
  为 `failed` 或 `uncertain`；验收上限：误命中次数 ÷ 元素记忆命中次数 **≤ 10%**
  （与 SC-002 一致，口径固定）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 不同措辞下复用同一控件记忆 (Priority: P1)

操作员反复跑同一批 GUI 回归用例。第一次成功点击某控件后系统写入元素记忆；第二次及
之后，即使 Planner 对本轮目标的自然语言描述措辞与写入时不同，系统仍应把该目标解析为
**同一元素身份**，从而命中既有记忆、在满足 015 既有安全门槛时跳过昂贵定位路径并直点。

**Why this priority**: 这是本 feature 存在的唯一直接理由——把实测恒为 0 的命中变成可复用
的正向收益。

**Independent Test**: 离线回归——同一物理控件、故意使用两种不同措辞的目标描述，完成
一次写入与一次查找；断言：解析出的身份相同、产生 element_memory 命中、定位模型调用被
跳过、后续独立验证仍执行。

**Acceptance Scenarios**:

1. **Given** 某控件已在某一画面身份下以身份 A 写入元素记忆（含模板与历史几何），
   **When** 后续轮次 Planner 用不同自然语言措辞指向同一控件，且画面身份匹配与模板校验
   均通过，**Then** 系统解析到身份 A、产生 element_memory 命中、跳过 Grounder 调用，并
   以记忆几何完成点击。
2. **Given** 写入时目标描述为短标签、查找时为目标的较长自然语言描述（或反之），
   **When** 两者指代同一控件且画面身份一致，**Then** 身份解析结果相同，允许命中。
3. **Given** 身份解析成功（候选唯一）但模板邻域校验未通过，**When** 进入命中判定，
   **Then** 系统 MUST NOT 直点，MUST 无损降级到 015 既有后续路径（候选提示或
   Grounder），且本事件可审计为「身份命中但模板未通过」而非「身份未命中」。
4. **Given** 身份候选唯一且历史连续成功次数很高，**When** 进入直点判定，**Then**
   系统仍 MUST 执行元素级邻域模板校验，MUST NOT 因高置信或连续成功跳过模板。

### User Story 2 - 不同控件绝不误并 (Priority: P1)

同一画面上存在多个可点击控件。系统在解析元素身份时，宁可漏命中，也不可把不同物理
控件合并为同一身份，以免错误坐标被复用。

**Why this priority**: 错误命中比零命中更危险——会直接制造误点击并污染记忆统计。

**Independent Test**: 离线用例——同一画面上两个几何位置不同的控件，分别写入；用各自
目标线索查找时身份不同；故意用仅文本相似但位置不同的线索查找时不得命中错误控件。

**Acceptance Scenarios**:

1. **Given** 同一画面身份下两个不同物理控件均已写入记忆，**When** 分别解析各自目标
   线索，**Then** 得到两个不同的元素身份，各自只能命中自己的记忆。
2. **Given** 两个控件可见文本相同或高度相似但几何位置明显不同，**When** 解析身份，
   **Then** 系统 MUST NOT 将二者合并为同一身份。
3. **Given** 身份解析结果不唯一或置信不足，**When** 进入命中判定，**Then** 系统
   MUST 视为未命中并降级，MUST NOT 猜测「最可能」的身份强行直点。
4. **Given** 同一画面身份下归一化文本相同的已存记忆 ≥2 条（不同网格单元，如表格多行
   同名控件），且当前线索无法把候选唯一收窄为 1，**When** 查找记忆，**Then** 系统
   MUST 未命中并降级，MUST NOT 按最近成功时间或序数猜测选取其中一条。

---

### User Story 3 - 写入与查询统一使用身份主键 (Priority: P1)

记忆的写入路径与查询路径 MUST 使用同一套身份定义与解析规则。自然语言描述降级为身份
解析的**输入线索之一**，不再充当存储主键或精确匹配键。

**Why this priority**: 若只改查询不改写入（或反之），会出现「新身份永远查不到旧记录」
的第二代零命中。

**Independent Test**: 单元/离线——同输入线索的写入与查询产出同一身份键；查询侧不得
再以原始自然语言字符串做唯一精确主键匹配。

**Acceptance Scenarios**:

1. **Given** 一次鼠标动作独立验证 `passed`，**When** 写入元素记忆，**Then** 记录以
   解析得到的元素身份为键（与所属画面身份关联），自然语言描述若保留仅作为线索/审计
   字段，不得单独决定主键相等性。
2. **Given** 查询时仅有 Planner 目标描述与当前画面观察，**When** 查找记忆，**Then**
   系统先解析身份再按身份检索，不得把描述字符串的 strip/lower 结果当作唯一匹配条件。
3. **Given** 无法从当前线索可靠解析身份（无线索、无匹配 OCR、矛盾、不唯一），**When**
   写入或查询，**Then** 写入 MUST 跳过可检索元素记忆；查询视为未命中；主流程 MUST
   继续（fail-open，不阻断测试）。

---

### User Story 4 - 存量记忆安全过渡 (Priority: P1)

线上或本地已存在的、以自然语言 `target_label` 为主键的 element 记忆记录，在启用新
身份逻辑后 MUST 整表作废或隔离，不得与新身份主键混用导致错命中；可靠记忆仅由新
运行按新身份重新写入建立。

**Why this priority**: 混用新旧主键会制造不可解释的偶发误命中，破坏「宁可不命中」
红线；旧键无法可靠反推结构化身份。

**Independent Test**: 准备含旧主键样本的记忆库；启用新身份逻辑后，旧记录零参与命中；
新成功点击写入新身份后可被后续命中。

**Acceptance Scenarios**:

1. **Given** 库中存在仅含自然语言主键的存量 element 记录，**When** 启用新身份逻辑
   并执行查找，**Then** 这些记录 MUST NOT 出现在可命中候选集（已删除或标记
   `legacy_invalid`/隔离，且查找过滤之）。
2. **Given** 旧记录已被作废/隔离，**When** 新逻辑对同一物理控件首次验证通过并写入，
   **Then** 仅新身份记录可被后续命中，旧记录不干扰。
3. **Given** 启用过程，**Then** MUST NOT 对旧记录做猜测式身份迁移，MUST NOT 以旧
   自然语言键与新身份键双轨同时参与直点。

---

### User Story 5 - 开关与回归安全 (Priority: P1)

工程师可关闭新身份主键能力；关闭后，记忆查找/写入的可观察行为与本 feature 合入前
一致（在相同输入与配置下逐字节一致的输出与副作用边界，沿用 015 对 `memory.enabled`
  的安全语义扩展到本能力开关）。

**Why this priority**: 命中逻辑变更靠近执行主路径，必须可瞬时回退。

**Independent Test**: 同一用例、同一记忆库快照，开关 off 时的 Grounder 调用次数、
记忆读写副作用与基线对齐；on 时出现身份解析与（在条件满足时）命中。

**Acceptance Scenarios**:

1. **Given** 本 feature 的专用能力开关为关闭（或总记忆开关关闭），**When** 运行任意
   用例，**Then** 不引入新的身份解析主键行为；不得因本 feature 改变既有未命中路径的
   输出与模型调用序列。
2. **Given** 开关打开，**When** 运行同一批回归，**Then** 在可复现条件下 element
   记忆命中次数 > 0（见 Success Criteria），且独立验证仍强制执行。

---

### User Story 6 - 命中、误命中与开销可观测 (Priority: P2)

工程师能从报告与结构化日志中区分：身份解析成功/失败、记忆命中、身份命中但模板失败、
以及「命中后独立验证失败」（误命中）。命中路径耗时可被单独统计。

**Why this priority**: 没有分项计数就无法证明「从 0 到有」与「误命中受控」。

**Independent Test**: e2e/离线——构造命中成功、身份未解析、模板失败、命中后验证失败
四类事件，断言报告字段与计数器分别递增；耗时字段存在且为非负。

**Acceptance Scenarios**:

1. **Given** 一次成功的元素记忆直点，**Then** 既有 `memory_hits.element_memory`（或
   等价汇总）递增，并记录本次使用的元素身份、画面身份、模板校验得分、被跳过的模型
   调用类型。
2. **Given** 记忆直点后独立验证失败或 uncertain，**Then** 系统将该次计为**误命中**
   （独立计数，不得仅埋在总失败里），并沿用 015 对失败记忆的抑制/计数语义。
3. **Given** 任意一次身份解析 + 记忆查找尝试，**Then** 审计中留下可汇总的耗时，使
   命中路径开销可离线计算分位值。

---

### Edge Cases

- 目标无线索（无匹配可见文本 OCR、画面身份未知等）→ 身份不可建立；写入 MUST 跳过
  可检索元素记忆；查找未命中。
- 同一画面多个控件共享完全相同的可见文本 → 必须依赖几何（网格单元）等维度区分；
  查询侧候选 ≥2 且无法唯一收窄 → 未命中（`identity_ambiguous`），不得按最近成功、
  序数或随机选一个。
- 控件无可见文本（纯图标）→ 身份 MUST 不可建立 → 不写可检索记录、查询未命中；
  MUST NOT 退回「整段 Planner 长描述当主键」。
- 纯符号串（仅 `×`、`/`、`--` 等，经归一化后仍非空）→ MUST 作为合法文本分量参与
  身份相等；同符号多钮 MUST 依赖不同 OCR bbox 中心所在网格区分，无法区分则未命中。
- Planner 描述与 OCR 可见文本冲突 → 不得仅因描述字符串相似而命中；以结构化身份规则
  为准，冲突时倾向未命中。
- 全半角/半角片假名/清浊音写法不同但经 FR-005a 归一化后相同 → 文本分量视为相等；
  未覆盖的假名变体或仅语义相近 → 仍不相等，不得模糊合并。
- 「小計」与「屏幕右下角的小計按钮」等子串关系 → MUST NOT 仅凭包含关系判定文本分量
  相等；须先从线索中抽取用于身份的可见文本（plan 定义抽取规则），再做归一化精确比较。
- 画面身份未匹配（页面指纹未达 015 高相似档）→ 不进入元素身份命中直点（保持 015
  页面门槛）。
- 分辨率变化导致几何不可比 → 不得强行缩放猜测命中；按 015 分辨率不一致封顶规则
  处理。归一化网格虽自描述，仍 MUST NOT 在页面分辨率不一致时做元素直点。
- 两控件 OCR 中心落入不同归一化网格单元 → 几何分量不相等，不得并成同一身份（即使
  可见文本相同）。
- 存量旧主键记录 → 启用时整表作废/隔离；即使物理行仍短暂存在，查找 MUST 过滤之，
  不得与新身份记录混匹配。
- 身份解析或存储异常 → fail-open：主测试流程不中断，本步按无记忆处理。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001（元素身份概念）**: 系统 MUST 定义稳定的**元素身份（element identity）**，
  作为元素记忆的逻辑主键。身份 MUST 至少由以下构成要素支撑：可归一化的可见文本、
  **画面归一化几何位置**、所属画面身份。几何分量 MUST 使用**被选中的可见文本 OCR
  项的 bbox 中心**的画面归一化坐标 \((x/w, y/h \in [0,1])\)，再映射到固定网格单元
  （grid cell）；**相等判定**中几何维度 MUST 以「同一网格单元」为准（容差 = 单元
  尺寸）。系统 MUST 另存绝对像素 bbox（如点击 `target_region`）供模板校验，但该
  像素框 MUST NOT 单独作为跨记录的身份相等键，也 MUST NOT 作为 `geom_cell` 锚点。
  身份 MUST NOT 使用应用容器相对坐标。网格粒度由 plan 配置化，语义固定为「量化
  单元相等」。其余性质见 FR-001a / FR-002 / FR-003。
- **FR-001a（身份键编码网格粒度）**: 可检索身份键 MUST 编码当前网格粒度 `G`（与
  schema 一并进入键前缀，形如 `eid-v1:g16|…`）。网格粒度变更后，既有记录的键前缀
  MUST 不再匹配当前前缀，因而 MUST NOT 被命中；purge 条件 MUST 将「非当前
  `{schema}:g{G}` 前缀」的行视为可清除的遗留键。
- **FR-002（身份稳定性）**: 对同一所属画面身份下的同一物理控件，在不同轮次、不同
  Planner 自然语言措辞下，身份解析 MUST 收敛到同一身份（在可用观察证据充分时）。
  身份 MUST NOT 依赖 Planner 措辞本身作为相等性依据。同一分辨率、同一画面身份下，
  **同源锚点**（被选 OCR bbox 中心）落入同一归一化网格单元时，几何分量 MUST 视为
  相等。写入路径与查询路径计算几何分量所用的锚点 MUST 为同一定义；验收 MUST 包含
  一组「同一控件先写后查、两侧 `geom_cell` 逐字符相等」的断言（不得仅断言最终命中）。
- **FR-003（身份区分性与保守性）**: 不同物理控件 MUST NOT 被解析为同一身份。当证据
  不足以唯一确定身份时，系统 MUST 选择未命中/不写入可检索记录，MUST NOT 猜测或放宽
  到可能误并的模糊匹配。OCR 中心落入不同归一化网格单元的控件 MUST 视为几何上不同。
- **FR-003a（多候选消歧）**: 在同一画面身份下，若按当前解析规则得到的可检索元素记忆
  候选集合大小 ≥ 2，系统 MUST 将本次查找视为未命中并无损降级，MUST 记录可审计原因
  （如 `identity_ambiguous`），MUST NOT 使用「最后成功时间最新」、随机选择、或未在
  身份键中编码的序数/方位猜测来强行消歧。仅当候选被唯一收窄为 1 条时，才允许进入
  后续模板校验与直点。
- **FR-004（领域无关）**: 身份的定义、归一化与解析逻辑属于核心代码，MUST NOT 包含
  任何被测应用、行业或场景专用词汇、字段名或分支（Constitution 原则 VI）。被测应用
  相关内容只允许出现在测试用例 YAML 与 fixture 中。文本归一化中的假名规则 MUST 是
  通用 Unicode/日文脚本处理，MUST NOT 硬编码业务同义词表。
- **FR-005（自然语言降级为线索）**: Planner（或其他上游）提供的自然语言目标描述
  MUST 仅作为身份解析的输入线索之一，MUST NOT 再作为元素记忆的精确匹配主键。
  仅 `strip`/`lower` 的描述字符串 MUST NOT 单独决定「是否同一元素」。
- **FR-005a（可见文本归一化）**: 参与身份相等的可见文本 MUST 先经确定性归一化流水线，
  **顺序与 research R4 完全一致**（不得另行排列）：(0) 空安全；(1) Unicode NFKC；
  (2) 半角浊点/半浊点与前一假名合并（若仍残留）；(3) 长音符号统一（ASCII `-` 不改
  为长音）；(4) 大小写折叠 `casefold`；(5) 空白折叠；(6) 不做清音≡浊音合并；
  (7) 精确字符串 `==` 比较。假名半角→全角等由 NFKC 与步骤 (2) 覆盖，具体金样由
  research R4 单测锁定。系统 MUST NOT 使用子串包含、编辑距离、同义改写或业务词表
  扩展来判定文本分量相等。**无可匹配的可见文本 OCR 项时，身份 MUST 视为不可建立**；
  写入侧 MUST 跳过可检索写入（查询侧无法仅从 `target_label` 推导几何；空文本可检索
  键只会永不命中并污染 SC-001 分母）。
- **FR-006（写入路径）**: 鼠标动作经独立验证 `passed` 且满足 015 既有写入前提时，
  系统 MUST 按本 feature 的身份解析结果写入/更新元素记忆。无法可靠解析身份时 MUST
  **跳过可检索元素写入**（可仍 upsert 页面记忆），MUST NOT 写入空文本可检索键，
  MUST NOT 回退到以原始自然语言串为唯一主键的写入。
- **FR-007（查询路径）**: 在 015 规定的记忆查找时机（如 `needs_grounding` 且无更高
  优先级计划占用时），系统 MUST 先解析当前目标的元素身份，再按（画面身份, 元素身份）
  检索；**仅当候选唯一**且后续门槛通过时方可直点。任一步失败 MUST 无损降级。
- **FR-007a（强制模板校验）**: 即使元素身份候选唯一，系统在直点前 MUST 执行 015 既有
  的元素级邻域模板校验（在记录坐标邻域内确认元素仍在）。模板未达标、模板缺失或校验
  异常时 MUST NOT 直点。系统 MUST NOT 因身份置信高、连续成功计数高或配置「高置信
  跳过」而省略该校验。
- **FR-008（与 015 门槛的关系）**: 本 feature MUST NOT 削弱 015 的页面相似度门槛、
  模板校验门槛、敏感区不写入、验证独立性（Constitution IV）与失败后本步抑制等安全
  语义；仅替换「目标是否同一」的判定主键。
- **FR-008a（误命中口径）**: **误命中** MUST 定义为：系统已执行元素记忆直点，且该次
  动作的独立验证结果为 `failed` 或 `uncertain`。误命中 MUST 可单独计数（FR-013），
  并触发 015 既有的失败计数/本步抑制语义。验收上限见 SC-002。
- **FR-009（存量数据策略）**: 启用本 feature 的新身份命中路径时，系统 MUST 将既有
  以自然语言 `target_label` 为主键的 `element_memories` 记录整表作废或隔离（删除、
  移入隔离存储或标记 `legacy_invalid`，具体物理手段由 plan 选定），使其 MUST NOT
  参与任何直点候选。此后仅按新身份规则写入的记录可命中。系统 MUST NOT 对旧记录做
  猜测式惰性迁移，MUST NOT 实施旧键与新键双写并行命中。页面记忆（page_memories）
  是否保留由 plan 决定，但 MUST NOT 因保留页面记忆而放行旧元素主键命中。
- **FR-010（能力开关）**: 系统 MUST 提供可配置开关，关闭后本 feature 引入的身份主键
  行为不生效，记忆相关可观察行为与合入前基线一致（并与 `memory.enabled: false` 的
  总关闭语义兼容）。
- **FR-011（无新模型调用）**: 身份解析与记忆命中路径 MUST NOT 新增任何模型调用；
  MUST NOT 改变 Planner / Grounder 的对外调用协议本身。
- **FR-012（范围排除）**: 本 feature MUST NOT 实现跨画面元素多对多索引，MUST NOT
  引入画面版本管理（均属后续 feature 026 范围）。
- **FR-013（可观测性）**: 系统 MUST 能分别统计至少：元素记忆命中次数、误命中次数
  （记忆直点后独立验证未通过）、身份解析不唯一次数（`identity_ambiguous`）、身份
  证据不足未命中次数（`insufficient`，可选汇总）、**身份解析/查找异常次数**
  （`identity_lookup_error`）、以及命中路径耗时。**`identity_lookup_error` MUST 与
  正常未命中**（证据不足 `insufficient`、多候选 `ambiguous`）在审计字段
  （如 `resolution_status=error`）与计数上可区分，MUST NOT 将异常静默记入普通
  miss。成功命中的审计 MUST 包含元素身份、画面身份、模板校验得分、被跳过的模型
  调用类型，以便离线核对「省了哪次定位调用」。
- **FR-014（跨场景契约）**: 凡声称通用的身份解析与命中行为，MUST 至少用两个互不相关
  的 GUI 场景（不同页面流程或不同应用 fixture）验证，防止实现只适配单一用例
  （Constitution 原则 VI）。

### Key Entities

- **ElementIdentity（元素身份）**: 某一画面身份下对物理控件的稳定标识。逻辑上由
  **经 FR-005a 归一化后的非空可见文本**、**被选 OCR bbox 中心所在网格单元**、所属
  画面身份、以及键中编码的网格粒度 `G` 等支撑；相等性不依赖自然语言措辞。绝对像素
  `target_region` 是附属存储（模板邻域），不是 `geom_cell` 锚点。
- **NormalizedVisibleText（归一化可见文本）**: 对 OCR 可见标签字符串按 research R4
  流水线处理后的结果；用于身份文本分量精确比较，不是 Planner 原文。空串表示不可
  建立可检索身份。
- **IdentityResolutionResult（身份解析结果）**: 对一次目标线索的解析产出，至少区分：
  唯一身份 / 不唯一（`identity_ambiguous`，候选 ≥2）/ 证据不足 / 解析失败；可附带
  用于审计的线索摘要与候选数量（非主键）。不唯一时不得选出「胜者」身份。
- **ElementMemory（元素记忆，015 已有，主键语义变更）**: 仍保存模板、历史几何、成功
  /失败统计等；检索主键从「自然语言 target_label」改为 ElementIdentity（并关联
  画面身份）。原始描述可保留为线索或审计字段。
- **PageIdentity / PageMemory（画面身份与页面记忆，015 已有）**: 元素身份的所属域；
  本 feature 不重新定义页面指纹算法，但命中仍受页面匹配门槛约束。
- **LegacyElementMemoryRecord（存量记录）**: 以自然语言主键写入的历史行；启用新身份
  后 MUST 被整表作废或隔离（FR-009），不得出现在可命中集合。
- **MemoryHitAudit / FalseHitAudit（命中与误命中审计）**: 记录身份、画面、模板分、
  是否直点、验证结果、耗时、跳过的模型角色等，支撑 Success Criteria 度量。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001（从零命中到正命中）**: 在与问题发现时相同的一批回归用例、相同环境假设下，
  启用本能力并完成至少一轮「先写入、后重跑」后，元素记忆命中次数 MUST 从基线 0 提升
  为 **> 0**，且元素记忆命中率（命中次数 ÷ 进入记忆查找的次数）MUST **≥ 30%**。命中
  率的分子分母定义 MUST 在报告中可核对。
- **SC-002（误命中上限）**: **误命中**口径固定为：已执行元素记忆直点，且该次独立验证
  为 `failed` **或** `uncertain`（与 FR-008a 一致）。该次数 MUST 可单独统计。在
  SC-001 同一批回归中：设 `hits = element_memory_hits`，
  `false_hit_rate = false_hits / hits`（hits=0 时 rate 为 null）。**最小有效样本量
  N = 20 次命中**（`SC002_MIN_HITS = 20`）：
  - `hits == 0` → 本条不适用（与 SC-001 同时验收时命中次数 MUST > 0）；
  - `0 < hits < N` → MUST 输出状态 **`sc002_inconclusive`**，MUST NOT 记为通过、
    MUST NOT 记为失败（小样本不稳，不得用 ≤10% 门槛硬判）；
  - `hits ≥ N` → `false_hit_rate` MUST **≤ 10%** 才通过，否则失败。
  「仅身份命中但因强制模板未通过而未直点」MUST NOT 计入误命中。
- **SC-003（命中路径开销）**: 单次「身份解析 + 记忆查找 +（若发生）模板校验直至给出
  命中或明确未命中」的耗时 MUST 可测量；在标准回归环境中，该路径的 **p95 ≤ 50ms**，
  且报告或性能摘要中给出实测 p50/p95（或等价分位）数字。**最小有效计时样本量
  M = 20**（`SC003_MIN_SAMPLES = 20`，与 SC-001 同批 manifest 上的 lookup 计时次数）：
  计时样本数 `< M` 时 MUST 输出 **`sc003_inconclusive`**，MUST NOT 记为通过、也
  MUST NOT 仅凭不足样本判失败；样本数 `≥ M` 时 `p95_ms` MUST **≤ 50** 才通过。
- **SC-004（关闭开关安全）**: 关闭本能力开关（及/或总记忆开关）时，在相同输入与配置
  下，与合入前基线相比：模型调用序列、记忆读写副作用边界、关键断言结果 MUST 保持
  一致（回归安全；「逐字节一致」适用于可确定性重放的离线/e2e 基线）。
- **SC-005（无协议/无新模型）**: 验收套件 MUST 证明：未增加 Planner/Grounder 协议字段
  要求；身份命中成功路径上 Grounder 调用次数相对未命中基线减少，且不引入额外模型
  角色调用。
- **SC-006（跨场景）**: SC-001 的「命中 > 0」MUST 在至少两个互不相关的 GUI 场景
  fixture 上分别成立，而非仅单一场景。

## Assumptions

- Feature 015 的页面指纹、页面相似度分档、邻域模板校验、敏感区跳过写入、验证独立性
  与 `memory.enabled` 总开关保持有效；本 feature 只替换元素级「是否同一目标」的主键
  语义。
- Planner 仍会为动作提供某种目标相关文本/描述线索；身份解析可以利用这些线索，但不
  依赖其措辞稳定。
- 几何信息在写入时通常可从已验证成功的点击/目标区域获得；查找时可能只有描述线索 +
  当前帧观察，解析器须在证据不足时保守失败。
- 身份几何采用画面归一化中心 + 固定网格量化相等；绝对像素 bbox 仅服务点击与模板，
  不做容器相对几何（黑盒无控件树）。
- 可见文本归一化采用 NFKC + 大小写/空白折叠 + 日文假名脚本折叠；不做子串/同义模糊
  相等。假名折叠表为通用脚本规则，不含业务词表。
- 同画面多候选（同文本不同网格等）一律未命中，不做最近成功或序数消歧。
- 身份唯一命中后仍强制邻域模板校验；不可高置信跳过。误命中 = 直点后 verify
  failed|uncertain，验收比 ≤10%。
- 存量 element 记忆采用**整表作废/隔离 + 新运行重建**；不作惰性迁移或双写并行命中。
  页面记忆可保留与否留给 plan，但不放行旧元素主键。
- 不改变 Constitution 原则 III 的整体动作优先级阶梯；本 feature 不实现 1.3.0 中的
  「已审批画面版本坐标索引直连」（属 026），仅修复 015 元素记忆主键。
- 性能目标 50ms p95 以本地弱配置回归机、无额外模型调用为前提，与 Constitution 资源
  约束一致。

## Dependencies

- **015-page-element-memory**：记忆表、写入/查找时机、模板校验、telemetry 骨架。
- **013-safe-click-point**：命中后点击点仍经安全点计算（若 015 已集成则保持）。
- **Constitution v1.3.0** 原则 IV（验证独立）、V（受控进化，不自动把噪声当真理）、
  VI（业务无关核心）。
- **非依赖 / 明确后置**：026 画面版本管理与跨画面元素索引；坐标索引直连定位阶梯的
  产品化。
