# Safety Requirements Checklist: 稳定动作身份与坐标空间定位纠正

**Purpose**: Validate that spec.md completely, clearly, and consistently defines the
safety-critical behaviors this feature exists to fix — action-identity stability under
Planner rewording, step-local `action_id` scoping, non-idempotent fail-safe behavior, the
sole no_effect retry condition, target drift detection, the pixel/normalized_1000
coordinate protocol, coordinate-space failure handling, the 1024×1568 portrait case, the
business-assertion/weak-assertion boundary, the click/keypress acceptance counts, and the
real-VNC manual-confirmation and no-auto-clear requirements. This checklist tests the
**requirements as written**, not the implementation.

**Feature**: [spec.md](../spec.md)

**Note**: This checklist was generated by `/speckit-checklist` and subsequently revalidated
against the completed spec/plan/tasks artifact set and Constitution.

## Requirement Completeness

      **Evidence** (gap found and fixed): FR-015 rewritten gives an operational test:
      "(a) 将该候选坐标分别代入 `pixel` 与 `normalized_1000` 两种解释后，MUST 恰好有一种

      约束、都不满足、或已有证据本身相互冲突，则视为无法可靠推断，MUST 按拒绝处理。"
- [x] CHK010 - FR-004's fail-safe trigger references "前一次同一逻辑非幂等动作" (the
      previous *same logical* non-idempotent action) as part of its precondition, while the

      determination is itself ambiguous — is this apparent circularity addressed anywhere
      in the spec? [Ambiguity, Spec §FR-004]

- [x] CHK011 - Is "结果展示元素"（result-display element, FR-008）defined with concrete,

- [x] CHK012 - Is the difference in requirement strength between FR-002 (MUST NOT) and

      **Evidence** (gap found and fixed): FR-005 now ends with: "本条使用 SHOULD 而非
