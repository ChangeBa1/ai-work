# Feature Specification: 截图去重、分析复用、性能可观测性与中文报告

**Feature Branch**: `[004-frame-dedup-observability]`

**Created**: 2026-07-22

**Status**: Draft

**Input**: User description: "为 VNC 黑盒 GUI 自动化测试 Agent 增加连续截图物理去重、重复图片分析复用、分阶段性能诊断，以及默认简体中文的 HTML 测试报告，同时保持确定性运行时、独立 Observe → Act → Verify、业务无关核心和完整审计轨迹。"

## Clarifications

### Session 2026-07-22

- Q: 配置敏感遮罩时，`ScreenFrame.content_hash` 和完全相同判定应基于哪组像素？ → A: 基于遮罩前的原始规范化像素，去重键另含遮罩配置身份。
- Q: `StructuredScreen` 应以什么粒度缓存，才能避免复用旧的逻辑采样上下文？ → A: 分别缓存内容分析组件，每帧重新组装 `StructuredScreen`。
- Q: 哈希、比较、缓存或持久化发生异常时，应采用什么安全回退策略？ → A: 优化故障降级为唯一帧和完整分析；持久化故障中止采集并进入既有错误流程。
- Q: 一个唯一帧因安全用途产生多个文件时，物理图片和避免写入应按什么单位统计？ → A: 每个实际持久化的截图文件计数，并按用途分类。
- Q: JSON 报告应如何兼容地呈现包括稳定性等待在内的完整逻辑采集轨迹？ → A: 新增顶层 `frames` 数组，包含全部逻辑帧。
- Q: 完整运行轨迹与“不保存重复图片”如何同时满足？ → A: 每次成功采集立即持久化新的不可变逻辑帧记录；唯一像素内容写入物理图片，合格重复帧通过内容寻址引用上一逻辑帧已认证的物理图片，不再写冗余 PNG。
- Q: 敏感输入步骤是否仍可持久化未遮罩 private 图片？ → A: 捕获策略声明禁止 private 持久化时不得创建未遮罩物理制品；模型只能短暂使用内存像素并及时释放，报告仍只引用安全遮罩证据。
- Q: 内容分析缓存能否跨越中间不同帧复用？ → A: 不能；本功能的 OCR、模板、diff 和视觉描述复用只对当前严格相邻且 `deduplicated=true` 的逻辑帧开放，A→B→A 的第三帧必须重新分析。
- Q: 页面未变化时何时跳过上下文敏感模型调用？ → A: 仅当确定性运行时证明请求语义及全部相关上下文未变化且当前阶段无需新决策时才记录 skip；任一上下文变化必须调用，操作后 Verifier 始终使用独立采集证据执行。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 连续截图只保存一次物理图片并保留每次逻辑采样 (Priority: P1)

作为测试运行维护者，我希望同一次运行和 VNC 会话中，相邻且采集范围完全一致的截图在像素完全相同时只保存一份安全物理图片，但每次采集仍形成独立、可审计的逻辑记录，从而降低磁盘占用而不损失运行轨迹。

**Why this priority**: 这是减少重复图片写入和报告图片复制的基础；如果逻辑采样也被合并，稳定性判断、动作前后证据和审计完整性都会被破坏。

**Independent Test**: 使用固定截图连续采集 10 次，检查逻辑采集记录、唯一物理文件、重复关系、稳定性计数和安全遮罩引用，即可独立验证该故事并量化节省量。

**Acceptance Scenarios**:

1. **Given** 同一 run、同一 VNC 会话、相同全屏范围、分辨率、像素格式及安全遮罩配置，**When** 连续采集 10 张规范化解码后逐像素完全相同的图片，**Then** 系统产生 10 条逻辑采集记录、1 份唯一物理图片，后 9 条记录均标记 `deduplicated=true`、引用正确的 `duplicate_of_frame_id` 和同一安全物理图片路径，且 `report_frames` 不复制重复图片。
2. **Given** 前 10 张截图完全相同，**When** 第 11 张只有一个像素发生变化，**Then** 第 11 张必须形成新的唯一物理图片和非去重逻辑记录。
3. **Given** 两张图片的像素内容相同，**When** ROI 坐标、full-screen/ROI 类型、分辨率、像素格式或安全遮罩配置任一不同，**Then** 系统不得将后一张物理去重为前一张。
4. **Given** 启用了敏感区域遮罩，**When** 后续截图命中去重，**Then** 逻辑记录和报告只引用与当前遮罩配置匹配的安全版本，未遮罩图片不得进入报告或本地公开制品。
5. **Given** `stable_frame_count=3`，**When** 三次相邻逻辑采样画面完全相同且后两次被物理去重，**Then** 三次采样均参与稳定性计数，页面可正常判定为稳定，并且后两帧均为 `changed_since_last=false`。
6. **Given** 当前步骤声明禁止 private 截图持久化，**When** 唯一帧或重复帧在敏感输入后被采集，**Then** 系统仍写入独立逻辑记录和安全遮罩证据引用，但不得创建或复用未遮罩 private 物理文件。

### User Story 2 - 完全相同图片复用内容分析而不绕过独立验证 (Priority: P1)

作为测试执行者，我希望仅依赖图片内容和分析配置的 OCR、模板识别、画面差异和视觉描述结果能够在连续完全相同的截图间复用，同时任何依赖当前步骤意图、动作历史、验证问题或重试策略的判断仍按其完整上下文执行，从而减少无效分析而不产生错误通过。

**Why this priority**: 重复模型和感知分析是主要的潜在耗时来源之一，但错误扩大复用范围会直接破坏 Planner、Grounder、Verifier 的职责分离和 Observe → Act → Verify 独立闭环。

**Independent Test**: 对相同图片分别执行相同和不同语义请求，核对纯内容分析调用数、上下文敏感结果复用条件以及操作无效果时的验证结论，即可独立证明节省与安全边界。

**Acceptance Scenarios**:

1. **Given** 连续 10 张完全相同且去重资格一致的截图，**When** 每帧请求相同配置的 OCR、模板匹配和视觉描述，**Then** 第一帧实际分析，后 9 帧复用相应感知结果，且每次复用均留下来源和缓存命中记录。
2. **Given** 第 11 张截图仅有一个像素变化，**When** 请求相同分析，**Then** 系统不得复用第 10 张的图片内容分析结果，必须重新分析。
3. **Given** 图片内容完全相同，**When** 验证问题、当前步骤意图、动作历史、重试策略、模型名称或版本、感知配置、遮罩配置、运行上下文任一相关项不同，**Then** 系统不得错误复用上下文敏感的模型答案。
4. **Given** 操作后截图与操作前截图完全相同，**When** 独立 Verifier 评估动作效果，**Then** 系统仍依据现有规则得到 `no_effect`、`failed` 或 `uncertain`，不得因截图或分析结果被复用而自动判定通过。
5. **Given** 页面未变化且确定性运行时判断无需形成新的步骤决策，**When** 进入下一次逻辑观察，**Then** 系统避免不必要的模型分析；若步骤意图或验证问题已改变，则仍执行所需的 Planner、Grounder 或 Verifier 判断。
6. **Given** 帧序列为 A→B→A 且第三帧与第一帧像素相同，**When** 第三帧请求 OCR、模板或视觉描述，**Then** 系统不得跨越中间帧复用第一帧结果，必须按新的唯一帧执行适用分析。
7. **Given** 页面未变化且请求语义及全部相关 Planner 上下文相同，**When** 确定性运行时确认当前阶段无需新计划，**Then** 系统记录一次 `model_call_skipped` 而不重复调用 Planner；Grounder 仅在确定性定位不足且上下文要求定位时调用，Verifier 对每个操作后观察仍独立执行。

### User Story 3 - 分阶段性能诊断与可核对的运行度量 (Priority: P2)

作为性能分析人员，我希望每次运行都提供采集、去重、持久化、感知、规划、定位、验证和报告构建的分阶段耗时及计数，从而能够基于证据定位瓶颈，而不是预先假设所有性能问题都来自重复图片。

**Why this priority**: 去重可以减少一类浪费，但只有完整度量才能确认实际收益、发现其他瓶颈并防止优化结论失真。

**Independent Test**: 运行包含唯一帧、重复帧、缓存命中、实际模型调用和阶段异常的固定工作负载，并交叉核对结构化日志、JSON 报告和 HTML 报告中的计数、耗时及异常标记。

**Acceptance Scenarios**:

1. **Given** 一次包含唯一帧和重复帧的完整运行，**When** 运行结束，**Then** 结构化日志、JSON 报告和 HTML 报告均呈现 `capture`、`pixel_hash`、`persistence`、`OCR`、`template`、`vision`、`planner`、`grounder`、`verification`、`report_build` 的已观测耗时。
2. **Given** 一次完整运行，**When** 汇总性能数据，**Then** 至少输出 `total_capture_count`、`unique_frame_count`、`duplicate_frame_count`、`dedup_ratio`、`physical_image_count`、`avoided_write_count`、`avoided_write_bytes`、OCR/template/vision 缓存命中次数、`skipped_model_call_count` 和实际模型调用次数，且各计数可与逻辑采集及调用轨迹核对。
3. **Given** 某个阶段发生异常或未完成，**When** 构建性能摘要，**Then** 该阶段明确显示失败、未完成或不可用，并保留已真实观测的数据，不用零值、估算值或成功状态伪造缺失数据。
4. **Given** 两次运行具有不同瓶颈，**When** 查看性能摘要，**Then** 用户可区分图片写入节省、内容分析复用和其他阶段耗时，而不会被引导为单一重复图片原因。

### User Story 4 - 获取完整、清晰且机器兼容的中文测试报告 (Priority: P2)

作为中文测试人员，我希望 HTML 报告默认以简体中文呈现所有主要可见信息，同时 JSON 报告继续保持稳定英文键名和内部枚举，使人工阅读体验改善且现有机器消费者不受破坏。

**Why this priority**: 报告是测试结果的主要交付物；中文化提高可读性，而兼容性约束避免破坏自动化集成。

**Independent Test**: 用包含中文用例名、所有主要状态、已知错误、原始错误详情、恢复记录、重复证据和性能摘要的固定运行数据生成报告，执行 HTML 快照、UTF-8 内容及 JSON 兼容性检查。

**Acceptance Scenarios**:

1. **Given** 未显式配置报告语言，**When** 生成 HTML 报告，**Then** 文档语言为 `zh-CN`，报告标题、用例、状态、开始/结束时间、步骤、迭代、验证结果、动作效果、失败原因、恢复记录、证据、前置条件、动作审计和性能摘要等主要可见内容均使用简体中文。
2. **Given** 内部状态为 `passed`、`failed`、`cancelled`、`uncertain` 或 `no_effect`，**When** 呈现在 HTML 中，**Then** 用户看到对应中文状态文本，而内部机器值和用于样式或自动化选择的稳定标识保持不变。
3. **Given** 报告包含已知错误码和原始错误详情，**When** 用户查看 HTML，**Then** 可见中文错误说明及未丢失的原始详情；JSON 中可新增本地化说明但原字段保持兼容。
4. **Given** 现有机器消费者读取 JSON 报告，**When** 功能启用，**Then** 原有英文键名、稳定枚举和字段语义保持不变，并可选择读取顶层 `frames`、`display_status`、`localized_message`、`performance_summary` 等新增兼容字段；`frames` 包含观察、稳定性等待、重试和验证中的全部逻辑采样。
5. **Given** 用例名称和错误信息含中文，**When** 生成并打开报告，**Then** HTML 和 JSON 均以 UTF-8 正确呈现，无乱码或字符丢失。
6. **Given** 多条逻辑证据记录复用同一安全图片，**When** 生成报告，**Then** 所有相同证据只引用同一物理文件，不在报告制品目录复制副本。

### Edge Cases

- 内容哈希相同但规范化像素比较不相同时，系统必须视为唯一帧；哈希只能用于内容标识和候选匹配，不能覆盖逐像素完全相同的判定。
- 两次采集跨越 run 边界、VNC 会话边界或中间夹有不同截图时，即使像素相同，也不得按本功能进行物理去重或沿用仅限相邻帧的分析复用关系。
- ROI 尺寸相同但坐标不同、full-screen 与等尺寸 ROI、遮罩区域相同但配置版本不同，均属于不同去重范围。
- 截图规范化、哈希、像素比较或缓存读写失败时，系统必须记录优化故障，把当前截图作为唯一帧按原有安全流程持久化，并执行全部适用分析；不得记录去重、缓存命中、避免写入或跳过调用。若物理图片持久化失败，则本次采集不得形成成功的 ScreenFrame 或参与后续验证，必须记录失败并进入既有确定性错误或恢复流程。
- 被引用的物理图片不可用、损坏或与记录的内容标识不一致时，报告不得静默引用错误证据，必须明确报告证据异常。
- 缓存条目存在但模型版本、分析请求语义或相关上下文信息缺失时，按不命中处理，不得猜测兼容。
- 某分析阶段返回部分结果后失败时，实际调用次数和已用耗时仍须记录，缓存命中和跳过调用不得虚增。
- `total_capture_count=0` 时，`dedup_ratio` 必须以明确、稳定且无除零歧义的方式表示为不可计算；其他计数仍需如实输出。
- 不支持的报告语言配置不得产生混合语言或空标签；系统按明确的配置校验错误或已声明回退规则处理，并留下记录。
- 当当前捕获策略禁止 private 持久化时，缓存命中、路径复用或故障回退均不得创建、引用或恢复未遮罩 private 物理制品；允许的内存像素必须在当前分析结束后释放。
- A→B→A 等非相邻重复内容不得命中本功能的连续帧分析复用；最近 3～5 帧窗口只限制资源生命周期，不扩大复用资格。

## Requirements *(mandatory)*

### Functional Requirements

#### 确定性控制、审计与范围边界

- **FR-001**: 系统 MUST 由确定性运行时决定采集、去重资格、缓存命中、分析路由、重试、验证和报告构建；模型不得自主改变这些流程规则或最终测试状态。
- **FR-002**: 系统 MUST 保持 Observe → Act → Verify 的独立关系；去重或分析复用不得用操作返回值、Planner/Grounder 自评或缓存命中本身替代操作后重新采集的证据和 Verifier 判断。
- **FR-003**: 系统 MUST 通过同一运行级逻辑帧记录器为每一次成功采集立即创建并持久化新的逻辑帧记录，无论是否产生新的物理图片；记录至少包含采集时间、`run_id`、`step_id`、唯一 `frame_id`、内容哈希字段、采集范围、VNC 会话身份、安全遮罩配置身份、`deduplicated`、`duplicate_of_frame_id`、`changed_since_last` 及实际引用的物理图片路径。观察、稳定性等待、重试和验证中的全部逻辑帧 MUST 进入 JSON 报告顶层 `frames` 数组，任何调用方不得绕过该记录器。
- **FR-004**: 系统 MUST 在每次运行中保留可审计的状态迁移、逻辑采样、去重决定、缓存命中或未命中、实际与跳过的分析调用、验证证据、异常和性能度量；复用结果必须引用来源记录，不得伪造一次新的模型调用或响应。
- **FR-005**: 核心需求、公共数据语义和行为 MUST 保持业务无关，不得包含 POS、购物车、支付或任何其他被测应用专用字段、关键词、状态、期望值或条件分支。
- **FR-006**: 功能范围 MUST 仅涵盖规范化像素逐像素完全相同的图片，不得将感知相似、压缩后近似或语义相同的画面视为本功能的重复图片。

#### 连续截图物理去重

- **FR-007**: 系统 MUST 将本次截图仅与上一张逻辑截图比较，并且默认仅在同一 run、同一 VNC 会话、相邻采集、相同 full-screen/ROI 类型与坐标、相同分辨率、相同像素格式和相同安全遮罩配置范围内允许去重。
- **FR-008**: “完全相同” MUST 同时满足采集范围、分辨率、像素格式、安全遮罩配置一致，以及遮罩前的原始截图经规范化解码后逐像素相同；`content_hash` MUST 基于该原始规范化像素计算，内容哈希相同本身不得作为最终充分条件。
- **FR-009**: 每个合格范围内的第一张图片 MUST 正常保存；后续完全相同的相邻截图 MUST NOT 写入新的 PNG 文件，也 MUST NOT 在 `report_frames` 中复制相同图片。
- **FR-010**: 只要任一规范化像素发生变化，系统 MUST 保存新的物理图片，创建非去重逻辑记录并触发适用的重新分析。
- **FR-011**: 去重逻辑记录 MUST 设置 `deduplicated=true` 和 `changed_since_last=false`，通过 `duplicate_of_frame_id` 指向被复用的先前逻辑帧，并引用其同一安全物理图片路径。
- **FR-012**: 唯一逻辑记录 MUST 设置 `deduplicated=false`；与上一帧像素不同时 MUST 设置 `changed_since_last=true`，首次采集则 MUST 明确表示无可比较的上一帧而不得声称发生变化。
- **FR-013**: 敏感区域遮罩与当前捕获持久化策略 MUST 在去重资格判断、持久化、缓存和报告引用全流程保持有效；不同遮罩配置或不同 private 持久化权限不得相互去重。未遮罩图片不得因路径或缓存复用进入报告或本地公开制品；密码输入或其他声明禁止 private 持久化的步骤不得创建或复用未遮罩物理制品，只能在策略允许时短暂使用内存像素。
- **FR-014**: 物理去重 MUST NOT 合并、删除或隐去逻辑采样，重复帧仍 MUST 计入 `stable_frame_count` 和采集总数。

#### 重复图片分析复用

- **FR-015**: 对完全相同的连续截图，系统 MUST 仅在当前逻辑帧已由严格相邻判等确认 `deduplicated=true` 时，分别复用仅依赖图片内容与各自分析配置的 OCR、模板匹配、screen diff、`describe_screen` 等内容分析组件结果；A→B→A 等非相邻内容不得命中本功能缓存。每个逻辑帧 MUST 使用实际或复用的组件结果重新组装新的 StructuredScreen。
- **FR-016**: 每类纯图片分析组件的缓存身份 MUST 至少包含基于遮罩前原始规范化像素的图片内容哈希、截图范围、遮罩/感知配置、分析类型以及适用的模型名称或版本；对于依赖前后两帧的分析还 MUST 包含相关两帧身份。最终复用仍须满足 FR-008 的完全相同边界。
- **FR-017**: 系统 MUST 分开管理纯图片内容结果与上下文敏感结果，不得仅因截图相同而无条件跳过依赖当前步骤意图、动作历史、验证问题、请求语义、重试策略或运行上下文的 Planner、Grounder、Verifier。确定性运行时 MUST 先比较规范化请求语义及完整相关上下文：任一项变化时执行所需调用；全部相同且当前阶段无需新决策时才允许记录确定性 skip。Verifier 对每个操作后的独立观察不得因图片缓存或 Planner skip 而省略。
- **FR-018**: 上下文敏感模型结果仅在图片内容、请求语义、模型名称或版本、模型配置及所有相关运行上下文均相同时 MAY 复用；任一项不同或缺失均 MUST 视为不命中。
- **FR-019**: 系统 MUST 由确定性路由规则及稳定的请求/上下文身份判断模型调用是否不再必要，并分别记录“纯内容缓存命中复用”与“流程判定无需调用”；两者不得混为同一指标。页面未变化、请求语义与完整 Planner 上下文相同且当前阶段无需新计划时 MUST 记录 Planner skip；上下文变化时 MUST 实际调用。
- **FR-020**: 重复截图 MUST 作为新的逻辑稳定性采样，并 MUST 创建具有本次 `frame_id`、采集时间、路径及变化字段的独立 StructuredScreen；该结果 MUST 明确产生 `changed_since_last=false`，不得从缓存带入旧逻辑帧身份、时间戳或虚假的 screen change 证据。
- **FR-021**: 当操作后截图与操作前完全相同时，ActionEffect 和 Verifier MUST 继续按现有规则判定 `no_effect`、`failed` 或 `uncertain`；缓存命中不得自动产生 `passed`。
- **FR-022**: 实际发生的上下文敏感模型调用 MUST 继续以可审计记录保留脱敏后的请求、响应、请求身份和关联上下文，并与 run、step、frame、iteration 及实际调用事件关联；确定性 skip 或允许的复用 MUST 保留来源、完整身份和原因，不得只记录计数或耗时。

#### 性能诊断与度量

- **FR-023**: 系统 MUST 独立记录 `capture`、`pixel_hash`、`persistence`、`OCR`、`template`、`vision`、`planner`、`grounder`、`verification`、`report_build` 各阶段的真实已观测耗时，不得预设重复图片是唯一性能瓶颈。
- **FR-024**: 每次运行 MUST 汇总 `total_capture_count`、`unique_frame_count`、`duplicate_frame_count`、`dedup_ratio`、`physical_image_count`、`avoided_write_count` 和 `avoided_write_bytes`；`physical_image_count` MUST 统计运行中实际持久化的每一个截图文件，并分别给出安全证据图片、私有模型图片和报告副本的用途分类计数。
- **FR-025**: 每次运行 MUST 分别汇总 OCR、template、vision 缓存命中次数，并输出 `skipped_model_call_count` 和实际模型调用次数；实际模型调用次数 MUST 能按适用分析类别核对。
- **FR-026**: 所有汇总计数 MUST 与逻辑帧、物理图片、分析调用和缓存事件一一核对；`unique_frame_count + duplicate_frame_count` MUST 等于 `total_capture_count`。
- **FR-027**: `dedup_ratio` MUST 使用 `duplicate_frame_count / total_capture_count` 的一致定义；总采集数为零时 MUST 明确表示不可计算而非伪造数值。
- **FR-028**: `avoided_write_count` MUST 按本应新增但因物理去重而未执行的实际截图文件写入次数统计；`avoided_write_bytes` MUST 基于对应用途的已持久化唯一文件实际字节数计算，并记录其计算依据。启用遮罩而同时需要安全证据和私有模型图片时，两类被避免的文件写入和字节均 MUST 如实计入。
- **FR-029**: 阶段异常、取消或数据不可用时，系统 MUST 保留已真实观测的耗时和计数，并明确标记其状态；不得以零值、估算值或成功状态替代未知数据。
- **FR-030**: 性能明细与汇总 MUST 同时进入带 `run_id`、`step_id`、状态、事件和耗时关联信息的结构化日志、JSON 报告及 HTML 报告。

#### 中文测试报告与兼容性

- **FR-031**: 系统 MUST 提供 `reporting.locale` 配置，默认值为 `zh-CN`，其契约 MUST 能在未来增加 `en-US` 等语言而无需改变内部稳定枚举。
- **FR-032**: 默认 HTML 报告 MUST 声明 `zh-CN`，并将报告标题、用例、状态、开始/结束时间、步骤、迭代、验证结果、动作效果、失败原因、恢复记录、证据、前置条件、动作审计和性能摘要等用户可见主要内容完整中文化。
- **FR-033**: `passed`、`failed`、`cancelled`、`uncertain`、`no_effect` 等内部枚举 MUST 在 HTML 中显示为对应中文；内部机器值、CSS class 和其他稳定自动化标识 MUST 保持不变。
- **FR-034**: 已知错误码 MUST 在 HTML 中显示中文说明，同时保留原始错误码和原始错误详情供排查；未知错误也 MUST 保留其原始详情，不得错误套用已知说明。
- **FR-035**: JSON 报告 MUST 保持原有英文键名、稳定枚举、现有字段类型和语义向后兼容；MUST 以新增顶层 `frames` 数组呈现全部逻辑帧，并 MAY 新增 `display_status`、`localized_message`、`performance_summary` 等其他可选兼容字段。不了解新增字段的现有消费者 MUST 仍可按原契约读取报告。
- **FR-036**: HTML、JSON 和相关文本报告制品 MUST 使用 UTF-8，中文测试用例名称、标签和错误信息不得出现乱码、替换字符或内容丢失。
- **FR-037**: 报告中的多条逻辑证据若引用同一安全图片，MUST 直接指向同一个已持久化安全物理文件，且不得在 `report_frames` 或其他报告目录复制出证据副本；报告副本用途分类计数在正常构建中 MUST 为零。

#### 明确测试与验收门禁

- **FR-038**: 功能 MUST 具备单元测试，覆盖完全相同判定、单像素变化、范围/ROI/像素格式/遮罩边界、逻辑与物理计数、缓存身份、上下文敏感复用门禁、异常度量和中文状态映射。
- **FR-039**: 功能 MUST 具备固定截图离线测试，至少覆盖连续 10 张相同图片、第 11 张单像素变化、相同内容不同 ROI、开启遮罩、不同验证问题和 `stable_frame_count=3`，且测试不依赖真实 VNC 或在线模型。
- **FR-040**: 功能 MUST 具备性能测试，用可重复工作负载核对阶段耗时完整性、计数守恒、避免写入字节数、缓存命中、跳过调用和实际调用次数，并证明重复工作量随重复帧减少。
- **FR-041**: 功能 MUST 具备 HTML 报告快照测试及 JSON 兼容性测试，覆盖全部主要中文标签和状态、UTF-8 中文内容、错误本地化、性能摘要及重复证据单文件引用。
- **FR-042**: 功能 MUST 使用至少两个互不相关的 GUI 场景建立跨场景契约测试，证明核心实现和报告契约不包含 POS、购物车、支付或其他业务特例；业务示例仅可存在于测试用例、fixture 或可选场景 profile。
- **FR-043**: 所有验收测试 MUST 能区分新的逻辑采集记录、唯一物理图片、复用的分析结果和上下文敏感验证结果，防止用单一文件数指标掩盖审计或验证缺失。
- **FR-044**: 规范化、哈希、像素比较或缓存读写异常 MUST 按缓存未命中和唯一帧处理，继续原有安全持久化及完整分析并记录异常；物理图片持久化异常 MUST 中止本次采集成功路径并交由既有确定性错误或恢复流程处理，不得以内存图片或缓存结果继续验证。

### Key Entities

- **Logical Frame（逻辑帧）**: 一次真实采集事件的审计记录；包含运行、会话、步骤、采集时间、范围、像素与遮罩身份、基于遮罩前原始规范化像素的内容哈希、变化状态、去重关系和物理图片引用。每次采集恰好产生一条，所有记录按采集顺序进入 JSON 顶层 `frames` 数组。
- **Physical Image（物理图片）**: 一个实际持久化的截图文件，按安全证据图片、私有模型图片或报告副本标识用途；同一逻辑帧在启用遮罩时可对应不同用途的物理文件。安全证据文件可被同一合格去重范围内的多个相邻逻辑帧和报告证据直接引用，但不得跨越规定边界误用。
- **Capture Scope（采集范围）**: 区分 full-screen 或 ROI，并描述坐标、尺寸、分辨率和像素格式，是完全相同判定及缓存身份的一部分。
- **Safety Mask Identity（安全遮罩身份）**: 能唯一表示当前敏感区域遮罩规则及其配置版本的身份；用于阻止安全边界不同的图片相互去重或复用。
- **Analysis Result（分析结果）**: 可独立缓存的 OCR、模板、画面差异、视觉描述或其他内容分析组件输出；记录分析类型、图片与配置身份、模型名称或版本、结果来源及实际调用或复用状态。它不携带可跨逻辑采样复用的 `frame_id`、采集时间或证据路径。
- **Context-sensitive Decision（上下文敏感判断）**: Planner、Grounder、Verifier 或其他依赖请求语义、步骤意图、动作历史、验证问题、重试策略和运行上下文的结果；只有完整上下文身份相同才可复用。
- **Stage Measurement（阶段度量）**: 某阶段的一次真实执行观测；包含关联运行/步骤、阶段名称、耗时、完成状态、异常信息及是否发生实际调用。
- **Performance Summary（性能摘要）**: 从逻辑帧、物理图片、分析事件和阶段度量汇总出的运行级可核对指标，同时呈现在结构化日志、JSON 和 HTML 报告中。
- **Localized Report Value（本地化报告值）**: 面向用户显示的中文标签、状态或错误说明；与稳定的内部机器值并存，不替换或重定义后者。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 对连续 10 张合格的完全相同全屏截图，运行结果恰有 10 条逻辑采集记录、1 份唯一物理图片、9 次避免写入，且 OCR、模板和视觉描述各仅发生 1 次实际图片内容分析。
- **SC-002**: 在第 11 张仅变化一个像素的验收数据中，第 11 张被 100% 识别为唯一帧并重新执行适用图片分析；不同 ROI 或不同安全遮罩配置的相同像素数据也有 100% 的边界隔离正确率。
- **SC-003**: 在相同图片配合不同验证问题或不同运行上下文的契约测试中，0 个上下文敏感答案被错误复用，且操作前后无变化的场景中 0 个步骤因缓存命中而被错误判定为通过；在请求语义及完整 Planner 上下文相同且无需新计划的固定场景中，重复 Planner 实际调用数为 0，同时每个操作后 Verifier 仍执行独立判断。
- **SC-004**: 当 `stable_frame_count=3` 且后两帧物理去重时，稳定状态在第 3 次逻辑采样后正常达成，逻辑采样计数准确率为 100%。
- **SC-005**: 每个完成运行的规定阶段、计数和缓存/模型调用指标在结构化日志、JSON 与 HTML 三种输出中均可找到；所有守恒关系和源事件交叉核对准确率为 100%，异常阶段不存在伪造数据。
- **SC-006**: 在 10 张相同图片的可重复性能验收中，物理图片写入和 OCR/template/vision 实际内容分析次数相对未复用基线均减少 90%，同时保留全部 10 次逻辑采集证据。
- **SC-007**: 默认 HTML 报告的规定主要可见标签和状态中文覆盖率为 100%，所有中文用例名与错误信息均通过 UTF-8 内容检查且无乱码。
- **SC-008**: 现有 JSON 报告兼容性样本全部继续通过，原英文键名、稳定枚举、字段类型和语义的破坏性变更数量为 0。
- **SC-009**: 单元测试、固定截图离线测试、性能测试、HTML 报告快照测试、JSON 兼容性测试及两个互不相关 GUI 场景的跨场景契约测试全部通过后，功能方可进入发布候选状态。
- **SC-010**: 两个跨场景契约测试中，与被测业务相关的核心固定字段、关键词或条件分支检出数量为 0，证明功能可复用于无关 GUI 场景。

## Assumptions

- 本功能默认采用严格的相邻帧、同 run、同 VNC 会话去重，不提供跨运行、非相邻帧或全局内容寻址去重。
- “规范化解码”表示在应用敏感区域遮罩前，将原始截图解码为可确定比较的像素序列；规范化只消除编码表示差异，不允许模糊、缩放、色差容忍或其他感知近似。
- 首个唯一安全截图仍按现有制品策略及时持久化；项目 Constitution 明确允许严格合格的重复帧立即持久化逻辑记录并内容寻址引用已持久化安全图片，而不是再次写入冗余 PNG。
- 敏感区域遮罩的现有定义和访问策略继续适用；捕获请求会明确给出 private 持久化权限，默认禁止保存的敏感输入步骤只生成安全遮罩物理证据，未遮罩像素最多短暂存在于内存。
- 现有 ActionEffect、Verifier、稳定性、重试和错误处理语义保持权威，本功能只减少符合严格条件的重复物理写入和重复分析，不改变通过标准。
- `en-US` 仅作为未来扩展能力的设计边界，本 feature 的交付范围是完整的默认 `zh-CN` 报告和对不支持 locale 的明确处理。
- 测试所需的固定截图、离线分析替身、现有 JSON 兼容性样本和两个互不相关的通用 GUI 场景可在项目测试制品中提供，且不要求在线模型或真实 VNC 才能执行核心验收。
- 本功能不引入感知相似去重、跨运行共享缓存、长期全局分析缓存、图片保留策略变更或生产模型/测试基线的自动修改。
