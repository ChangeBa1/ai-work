### 5. 数据绑定模式的使用

一、什么是 MVC

MVC（Model-View-Controller） 是一种软件架构模式，将应用程序分为三个核心部分：

Model（模型）

  • 负责业务逻辑和数据 — 是什么、怎么算、有什么规则
  • 不依赖 UI，可以独立测试
  • 状态变更后通知观察者（View/Controller）

View（视图）

  • 负责展现 — 用户看到和交互的界面
  • 从 Model 读取数据（不直接修改 Model）
  • 将用户操作转发给 Controller

Controller（控制器）

  • 负责协调 — 接收用户输入，转化为对 Model 的操作
  • 决定哪个 View 响应，以及 Model 变化后如何更新 View
用户操作
   ↓
Controller  ←──────┐
   ↓                │ 读取
Model ──→ View ─────┘

MVC 核心原则是分离关注点：UI 和业务逻辑彼此独立，Controller 是胶水层。

二、POS4U 客户端的 MVC 体现

POS4U 客户端不是标准的 MVC（如 ASP.NET MVC），也不是 MVVM。它采用了一种事件驱动的 Command 模式 + 状态机 + 观察者的自定义架构，但其角色划分与 MVC 高度对应：

经典 MVC POS4U 对应 具体实现
Model Transaction 层 + POSData CommonTranBase 子类（SalesTran 等）+ POSData 全局状态
View ScreenBase 子类 WPF UserControl，继承 ScreenBase
Controller Command 层 + WinPOSController CommandWinPOSBase<T> 子类 + 框架的中央调度引擎

具体来看三层

1) M — Model（模型/业务层）

业务逻辑封装在 Source\Business\ 下的 Tran（Transaction） 类中。每个交易类型是一个状态机。

public class Sales_Total : CommandWinPOSBase<StringInputData>
{
    public Sales_Total() : base(EventCodes.Sales_Total) { }

    protected override bool OnExecute(string deviceId, StringInputData inputData, POSData posData)
    {
        var tran = posData.CurrentTran as SalesTran;

        // 检查信用卡组合使用限制
        if (tran.PaymentObject.Items.Any(p => p.PaymentType == PaymentTypes.Credit))
        {
            tran.SetError(MessageIds.ErrorCannotSalesCreditCombinedUse);
            return false;
        }

        // 执行支付逻辑（调用 Model）
        if (!tran.AddPayment(PaymentTypes.Cash.Code, inputs))
            return false;

        // 结束交易
        return tran.EndTran();
    }
}

对照 MVC：这里的 CommandWinPOSBase<T> 子类就是 Controller — 它接收事件输入，调用 Model 的方法执行业务逻辑，Model 状态变更后由框架自动通知 View 更新。

三、为什么它看起来"不像"典型的 MVC？

  1. Controller 没有显式的类名 — 它不叫 SalesController，而是叫 Sales_Total、Sales_AddLineItem 等 Command。每个命令处理一个具体的事件粒度，而不是一个实体的 CRUD。

  2. View 不绑定 ViewModel — 它直接从 POSData（全局 Model 上下文）读取数据，而非通过 ViewModel 属性。

  3. 使用状态机而非双向绑定 — 界面导航通过 UIMapper（将 TranType + CurrentState 映射到 ViewId + DialogId）驱动：

// WinPOS/UI/WinPOS.UI.UIMapper/UIMapper.cs
public ViewId MappingView(POSData posData)
{
    var tran = posData.CurrentTran.OperatingTran;
    return this._tranTypeViewMap[tran.TranType];
    // TranTypes.Sales → ViewIds.Sales
    // TranTypes.MainMenu → ViewIds.MainMenu
    // ...
}
  1. 观察者模式替代事件总线 — IObserver 接口让多个订阅者（UI、打印机、设备监控）在 Model 变更后各自更新，这是为了满足 POS 系统的实时性要求：打印机必须在交易确定一瞬间开始打印，不需要 View 中转。

总结

经典 MVC POS4U 客户端
Model 领域对象 + 数据 CommonTranBase 子类 + POSData
View 模板/组件 ScreenBase 子类（WPF UserControl）
Controller 路由 + Action CommandWinPOSBase<T> Command 类 + WinPOSController 调度器
数据流 用户 → Controller → Model → View 事件 → Command → Model（POSData）→ Observer → View
特性 每个 Model 一个 Controller 每个 EventCode 一个 Command，细粒度命令模式

所以结论是：POS4U 客户端本质上是一个 MVC 架构，但它的 Controller 层采用了命令模式（Command Pattern）来分解，Model 层采用了状态机模式（State Machine），View 之间的切换通过 UIMapper（策略模式） 来完成。你可以把它理解为 "事件驱动的 Command-MVC" 变体。
