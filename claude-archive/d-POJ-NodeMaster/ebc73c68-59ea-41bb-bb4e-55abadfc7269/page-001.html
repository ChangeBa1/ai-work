3. 关键逻辑 walkthrough

该文件是 CESettingToolV4 的运行时配置中枢，通过以下方式被使用：

  1. 启动安全检查（L4-L5）：StartPassword 如果非空，工具启动时需要验证密码。
  2. 环境选择机制：V4 工具支持 4 套环境（Mercury/生产、Venus/备用、Test/测试、Local/本地开发），从 L28-L119 的配置中，每套环境都有独立的网络地址和访问密钥/令牌。
  3. 默认设备分配（L16-L25）：Charge（充值机）和 Payment（收银机）各有不同的默认找零机和打印机型号，充值机用 ACE-100A，收银机用 ECS-77。
  4. 外部服务集成（L47-L129）：ValueCard（电子货币）、PointService（积分）、CRM PointService、RetailMediaService（零售媒体广告）这 4 个外部服务通过 HTTPS/SOAP 协议集成，每个服务都有环境级的 URL 和访问凭据。
  5. Logo 部署（L131-L139）：从 .\CESettings\TopLogo\ 读取 Logo 文件，部署到 C:\POS4UGO\Settings\ 目录下。
  6. DB 初始化（L141-L147）：指定需要更新门店代码和需要删除的表清单文件名，用于工具执行数据库初始化操作。
  7. 终端编号规划（L153-L159）：收银机终端号以 45 开头，子终端号以 40 开头。

4. 关键函数 / 类 / 组件说明

无函数/类。以下为关键配置域分析：

  • AES 加密密钥（L48-L55，L122-L129）：ValueCard 和 RetailMediaService 的访问密钥以 Base64 编码存储，读取时需要 AES 解密。Test/Local 环境使用不同于生产环境的密钥链。
  • CRM PointService 令牌（L92-L99）：生产环境用简单的明文字符串 "s8b3n9"，Test/Local 用 MD5 散列值 "82b33ca1cdd8b7abe4d16795c0ccc3bd"。这种差异可能意味着生产环境的令牌由其他安全管理机制保护。
  • 点分十进制 IP（L73-L80）：PointService 使用内部 IP 而非域名，说明其部署在内部网络。

5. 依赖关系

  • 依赖 HTTP/HTTPS 网络访问（所有 Service URL）。
  • 依赖 SOAP 协议（ValueCardDealServiceURL 使用 /soap/services/ 路径，CRM 使用 .asmx）。
  • 依赖 AES 解密算法（读取 ValueCardAccessKey 和 RetailMediaServiceAccessCode 时）。
  • 依赖 Logo 文件（TopLogo.bmp）存在于 LogoFolderPath。
  • 依赖两个 .txt 表清单文件（L142-L147）。
  • 依赖 PointService 服务器（L73-L89）可通过 TCP 51001 端口访问。

6. 错误处理与边界情况

  • StartPassword 为空（L4-L5）：启动时不进行密码验证，直接进入工具主界面。
  • ExternalServiceVisible=False（L6-L7）：外部服务配置页面在 UI 中隐藏，防止操作员随意修改生产环境配置。
  • Base64 密钥解析失败（L48-L55、L122-L129）：如果密钥数据损坏，AES 解密会抛出异常，需要 C# 代码的 try-catch 处理。
  • 表清单文件缺失（L142-L147）：如果 CESettingTool_UpdateTableList.txt 或 CESettingTool_DeleteTableList.txt 不存在，DB 初始化步骤会失败。
  • 默认公司编码拼写错误（L10）：DefaultComanyCode 中 "Comany" 是 "Company" 的拼写错误，在代码中必须保持一致。如果代码中误写为 DefaultCompanyCode 则无法匹配。
