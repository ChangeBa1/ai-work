8. 新人阅读建议

  1. 区分自动生成代码与手写代码：文件头 L1-L9 和 [GeneratedCode("System.Data.Design.TypedDataSetGenerator", "16.0.0.0")] 属性（L42）明确标识这是自动生成文件。新人不要手动修改此文件，修改 .xsd 设计器文件后重新生成即可。

  2. 阅读顺序建议：

  3. 先看 L25 的 CommonDataSet 类定义和 L321-L338 的 InitClass() → 了解包含哪些表
  4. 然后看 TableAdapter 部分（L2779-L2795 的 InitCommandCollection）→ 了解如何连接到数据库（存储过程和连接字符串）

  5. 最后看 Row 类（L2112-L2441）→ 了解每行数据的属性访问方式和异常处理

  6. 数据流理解：典型使用流程是业务层创建 CommonDataSet 实例 → 调用 TableAdapter.Fill(dataSet) 填充数据 → 在内存中修改 → 调用 TableAdapterManager.UpdateAll(dataSet) 写回数据库。

  7. 特别注意两个连接字符串：POS4UCLOUD_V4ConnectionString（5 个 TableAdapter 共用）和 POS4UBackgroundConnectionString（仅 BOStoreManagementTableAdapter 使用），它们的配置在项目的 Settings 文件中。

  8. StoreInformationMasterRow 的 StoreCodeName 特殊行为：StoreCodeName 列被标记为 ReadOnly = true（L866），但列本身仍允许 DBNull。getter 在 null 时返回 string.Empty（L2174-L2177），这与 StoreName 的行为一致。

9. 不确定点

  2. 存储过程的 DDL：6 个存储过程（usp_BOGetCodeMaster 等）的 SQL 定义不在本 batch 中，需要结合 SQL Server 项目文件或数据库脚本来确认其查询逻辑。

  3. BOStoreManagementTableAdapter 使用不同连接字符串的原因：需要结合 Settings 文件（Properties.Settings.Default.POS4UBackgroundConnectionString vs POS4UCLOUD_V4ConnectionString）和业务逻辑确认这是否指向同一个数据库的不同连接凭据，还是完全不同的数据库。

  4. 是否有对应的 .xsd 文件和手写 partial class：CommonDataSet 标记为 partial class（L25），需要结合 CommonDataSet.cs（非 Designer）确认是否有手写的业务逻辑扩展。
