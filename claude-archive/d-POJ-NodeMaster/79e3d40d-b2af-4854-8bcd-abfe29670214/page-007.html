### Q14：解释"确实停止循环处理、重置完了判定"中的"确实"和"コマンド"

- **"确实"** = 真正停住，不是只停定时器。案1 只 `StopTimer()`（关了定时开关），后台 while 线程还在跑；案3 补 `_isChecking=false` 让 while 退出
- **"コマンド"** = `Sales_NotifyCustomer`——通知「这笔交易已确认/已转交」的指令

### Q15：案1 和案3 只有一个 `_isChecking=false` 的区别吗？

**不是**。核心区别在**状态守卫**（案1 完全没有）：

| | 案1 | 案3 |
|---|---|---|
| ① 发命令前状态守卫 | ❌ 无 | ✅ `CurrentState==SendMTransaction` 判断 |
| ② BtnRetry 停线程 | ❌ 只 `StopTimer()` | ✅ 补 `_isChecking=false` |
| ③ BtnRetry 重置标志 | ❌ 无 | ✅ 补 `_isFinished=false` |

案3 = 案1 的方向（修好 BtnRetry 漏洞）**＋** 发命令点状态守卫（案1 完全没有的核心防御）。即使把②③拿掉，只要有①，bug 也发不出来。

## 8. 补足

### 案3 为什么不能简单 `_isChecking=false` 停 while？

while 循环的退出条件只有 `CheckMTransactionOperationState != Notyet`（`_isChecking` 不是退出条件——它只是防止并发 while 的标志）。所以 `_isChecking=false` 不能直接停 while。

有了**状态守卫**后：在 `WaitingReInquiry` 状态下 `CheckMTransactionOperationState` 持续返回 `Notyet` → while 继续跑。直到推送把状态推回 `SendMTransaction` → 轮询下一次检查时状态匹配 → 正确发 `NotifyCustomer` → return `Already` → while break。

因此案3 的正确理解是：**状态守卫让轮询在状态不对时"不发命令但继续等"**，而非"立即停掉轮询"。
