Excel File Workflows

CRITICAL: Use Formulas, Not Hardcoded Values

Always use Excel formulas instead of calculating values in Python and hardcoding them. This ensures the spreadsheet remains dynamic and updateable.

❌ WRONG - Hardcoding Calculated Values

# Bad: Calculating in Python and hardcoding result
total = df['Sales'].sum()
sheet['B10'] = total  # Hardcodes 5000

# Bad: Computing growth rate in Python
growth = (df.iloc[-1]['Revenue'] - df.iloc[0]['Revenue']) / df.iloc[0]['Revenue']
sheet['C5'] = growth  # Hardcodes 0.15

# Bad: Python calculation for average
avg = sum(values) / len(values)
sheet['D20'] = avg  # Hardcodes 42.5

✅ CORRECT - Using Excel Formulas

# Good: Let Excel calculate the sum
sheet['B10'] = '=SUM(B2:B9)'

# Good: Growth rate as Excel formula
sheet['C5'] = '=(C4-C2)/C2'

# Good: Average using Excel function
sheet['D20'] = '=AVERAGE(D2:D19)'

This applies to ALL calculations - totals, percentages, ratios, differences, etc. The spreadsheet should be able to recalculate when source data changes.

| **逻辑问题** | 报告把机理解释（待机残压需完全放电 ⇒ PSU / 主板常电域故障）建立在「只有拔电才管用」这个**排他性**上，但这个排他性**从未被验证**。下次故障时先长按电源键 5–10 秒强制关机再开机——若软复位**也**能恢复 ⇒ 是芯片组 / BIOS / Super-I/O 的锁存状态问题（可能靠固件 / 设置绕过）；若**只有**断 AC 才恢复 ⇒ 才真正指向 +5VSB 待机域。 |
| **影响** | 报告在一个**从未实验过的变量**上得出了机理结论。 |

### 3. 报告自己的数据其实指向 Intel ME / +5VSB 待机域，却被忽略

三条独立线索都指向 +5VSB / Management Engine 域：

1. 电源线**常时插着过夜** ⇒ +5VSB 整夜带电；
2. 恢复**必须物理拔 AC** ⇒ 完全放掉 5VSB；
3. 恢复启动日志里有 **MEI（Management Engine Interface）和 zzwdt（看门狗）** 事件（256 / 3100 / 4201）。

- **逻辑问题**：ME 卡死正是这种症状（黑屏、POST 不交接、无日志），且**只有完全断 AC 才能复位 ME**，短重启不行——与「短断电能正常启动」完全吻合。报告只把 NetBT 4307 / Server 2511 判为「良性」，却**完全没分析 zzwdt/MEI**（是被忽略，不是被排除）。
- **影响**：这个假说可能比「电容老化」更贴合报告自己的事实，却根本没进入候选。

### 4. 最贴合的替代原因被「凭空排除」：硬盘冷启动起转、USB 外设

「首次冷启动（断电 15–19 小时后）黑屏、电源灯亮、无日志、断电再通电立即恢复、13 年老机（极可能还是原装机械盘）」——这是 **HDD 主轴电机静摩擦（stiction）/ 冷态起转困难**的教科书式画像，其经典现场对策**正是**一次 AC 断通。同样地，「只有拔 AC 才恢复」也**同样**符合 USB 外设反向馈电 / 拖累 +5VSB 的情形（拔 AC 会同时切掉 USB 待机电）。

报告只点名「主板 / 电源电容」，却没用最便宜的测试排除这两类。建议判别手段几乎免费：**冷启动时拔掉全部 USB 设备**；故障启动时**听 / 测硬盘是否起转**；用已知良好硬盘冷启动。

### 5. 触发条件（断电 15h+）从未复现，n=2 且无基线，置信度被高估

- **报告说法**：复现关键是「断电 15 小时以上的当日首次启动」。
- **逻辑问题**：
  - 验证只做到约 1 小时放置，**且是当天恢复后做的**——同时把「断电时长」和「恢复后状态」两个相关变量都压在安全侧。真正的特征事件复现次数 = **0**；这种「未复现」对结论真假几乎没有判别力。
  - 结论建立在连续两天的 n=2 上，**没有基线**（之前多少次「当日首次启动」是成功的，未知）。这个模式可能是巧合、环境因素、或最近才引入的回归，而非老化。
  - 「当日首次启动」这个框定**部分是循环的**：既然恢复手段就是拔电再启动，那么当天剩下的启动当然都成功——任何「需断电复位才能启动」的故障都会呈现为「首次启动失败」。
- **建议**：把「最可能原因」降级为「候选假说」。至少做一次（最好多次）15–19 小时冷断电复现，并把「过夜插电」与「过夜拔电」作为两个独立单元格分别测。

### 6. CMOS 电池列为「高优先级」与报告自身的关键症状相矛盾

| | |
|---|---|
| **报告说法** | 对策②换 CMOS 纽扣电池（高优先级、便宜易行）。 |
| **逻辑问题** | 纽扣电池域**故意设计成独立于 AC**；而在 AC 插着过夜期间，是 +5VSB（不是纽扣电池）在维持 CMOS，所以故障区间内纽扣电池根本没被消耗。CMOS 电池耗尽的典型表现是「CMOS checksum bad / RTC 走时不准 / BIOS 恢复默认」（**有可见的 POST 文字**），而非无声的黑屏不开机；而且如果电池真没电，拔 AC 恢复时反而更容易**破坏** CMOS，而不是干净地恢复启动。报告**没有任何 CMOS 症状**（无走时偏移、无 checksum 报错），却把换电池排第二优先。 |
| **影响** | 报告最强的证据（只有拔 AC 才恢复、线常插过夜）**指向远离**纽扣电池，而非指向它。这是结论与对策之间的**内部不一致**。 |
| **建议** | 把 CMOS 电池降为「老旧硬件的常规保养项」，并明确说明恢复机理并不支持它；要么先采集 CMOS 证据（过夜后 RTC 是否偏移、恢复启动是否出现 checksum / 默认加载提示）再决定优先级。 |

## 🟡 中严重度（2 项）

### 7. 电容机理无任何电气测量；计划做的「目视检查」与该主板不匹配

报告断言「电解电容老化导致电源时序异常」，却**没有 ESR 测试、没有纹波 / 示波器、没有 PWR_OK 捕获**。而 2012–2013 年的 Ivy Bridge / ChiefRiver 板，CPU VRM 和 bulk 滤波大量使用**固态聚合物电容**——聚合物电容**不会鼓包漏液**，所以「开箱看鼓包 / 漏液」可能**结构性地查不出**所假设的缺陷。结果「目视干净」会被误读成「主板没问题」，却并不能为主板洗清嫌疑。

老旧电解电容典型是在**负载 / 发热**下失效（起转、运行中），而非「轻载待机浸泡 15 小时后立即恢复」——与观察到的时间特征**吻合度偏低**。

### 8. 「长时间断电」与温度 / 时段 / +5VSB 待机浸泡相混杂；15h+ 阈值未测

一段长夜间间隔**同时**改变了：断电时长、环境温度（早晨冷机）、湿度、以及约 15 小时的 +5VSB 连续带电。报告挑了「断电时长 / 电容放电」，却没有一个测试能把「断电时长」与「温度 / 机械状态」分开。**冷焊点 / 热胀冷缩断路**、**HDD 冷态粘连**同样能拟合这两个数据点，指向的却是重焊 / 换盘，而非电容 / 电源。

由于「线常插过夜」，断电时长与 +5VSB 待机浸泡在两次事件里**不可分离**，报告却单挑了断电时长当关键。建议把阈值如实表述为「介于 1h 与 15h 之间、未知」，并用「15h 断电 + 暖机 vs 15h 断电 + 冷机」「过夜插电 vs 过夜拔电」两组单元格去混杂。

## 🟢 低严重度（2 项有效）

- **POST 蜂鸣码从未观察 / 记录**。AMI BIOS 上蜂鸣码是免费的内置判别器（能区分内存 / 显卡 / CPU 与 pre-CPU 的供电停滞），连「是否有蜂鸣器」都没说明。在没用它的情况下断言「POST 层硬件故障」，定位的特异性偏弱。
- **「电源灯亮」被过度解读为「略可放心」**。电源灯只证明前面板 +5V（多由 +5VSB 派生）在场、且按键被 Super-I/O 登记；它对 CPU 是否执行、内存训练、POST 进度**几乎不携带信息**，HDD 起转卡住同样会是灯亮。应作为中性观察，不从中读出「安心」或因果。

> 综合阶段还产生了一条被判定为**无效（strawman）**的批评——「ping 不通不能说明机器没启动」——已过滤。报告把黑屏 + 无 ping + 无 RDP + 无日志**四者合用**来排除「Windows 已启动只是显示坏了」，这一推断是成立的。

## ✅ 报告做对的地方（为求平衡）

- **边界推断部分正确**：「无日志 + 无 ping + 无 RDP + 黑屏」确实排除了「Windows 已启动、仅是显示故障」，把故障锁定在「未到达可联网的 Windows 状态」——这一步是站得住的，问题只在于它**过头**到了「硬件」。
- **诚实**：明确承认 15h+ 冷启动复现**未做**、列为今后课题，没有谎称已复现。
- **时间算术正确**：约 19h、约 15.5h 断电，以及「两次都是长时间断电后的当日首次冷启动」的关联观察准确。
