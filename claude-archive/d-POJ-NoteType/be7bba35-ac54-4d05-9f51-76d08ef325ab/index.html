二、根本原因（已通过代码 + 团队自身分析双重验证）

核心机制：每行明细数量上限 = 999

SettingValues.cs:38 定义了「商品数量的最大值」：

public static SettingValue<int> LimitQuantity { get; } = new SettingValue<int>(nameof(LimitQuantity), 999);

触发点：还原过去的交易时，对每行重新应用数量

读取过去交易后，RestoreTranObject.cs:618-625 的 RestoreLineItems 会对每一行 Quantity != 1 的明细，重新调用 ChangeQuantity：

if (lineItemRow.Quantity != 1)
{
    // 数量変更
    if (!tran.ChangeLineItem<LineItemBase>(lineItem, l => l.ChangeQuantity(tran, lineItemRow.Quantity.ToString())))
        return false;
}

LineItemBase.cs:180 的 ChangeQuantity → LineItemCommonLogic.cs:71-75 的 TryParseQuantity 执行上限校验：

// 最大値チェック
if (quantity > SettingValues.LimitQuantity.Value)   // 999
{
    tran.SetError(MessageIds.ErrorItemQuantityMaxOver);   // Code 1809
    return false;
}

结论：单个明细数量 ≥ 1000 时，还原在 > 999 处失败 → ErrorItemQuantityMaxOver → 整个还原中止。 边界恰好是 1000，因为上限是 999（off-by-one），代码中并没有字面量 1000。
